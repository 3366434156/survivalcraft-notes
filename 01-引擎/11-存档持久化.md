## 核心机制

### 三条数据流汇到 ValuesDictionary

`ValuesDictionary` 就是 `Dictionary<string, object>`（ValuesDictionary.cs:9）。`GetValue<T>(key)` 未命中抛 `Required value "key" not found`（:38-43）；命中只做 `(T)value` 硬拆箱（:40），**不做任何数值转换**——float 写入、int 读出即 `InvalidCastException`。带默认值重载（:45-50）未命中给默认、类型不符**仍抛**；`SetValue` 覆盖不抛（:52-54）、`Add` 重复键抛（:56-58）、`TryGetValue` 类型不符也抛。键比较大小写敏感。

模板→实例：`.xdb` 的 `DatabaseObject` 按继承链摊平成袋（`PopulateFromDatabaseObject`，ValuesDictionary.cs:107-125，键=对象 Name）；实体构造时模板袋里 `<Values Name="某组件">` 子袋原样交给组件，成为其 `ValuesDictionary`（Component.cs:12/:41）。存档→实例：世界加载把存档 XML `ApplyOverrides` 盖在同一袋上（EntityData.cs，ValuesDictionary.cs:127-184；`overrideExistOnly=true` 时新键静默丢弃）。**模板参数与存档值住同一个袋子**。

### 加载全链（进世界）

`PlayScreen.Play` → `GameManager.LoadProject`（GameManager.cs:32）→ `DisposeProject`（:33）→ 打开 `<世界目录>/Project.xml` → 解析 XElement、派 `ProjectXmlLoad` 钩子（:47-55，先旧签名再新签名）→ `new ProjectData(游戏库, projectNode, overrides, ignoreInvalidEntities:true)`（ProjectData.cs:26-54：读 `<Subsystems>` 与 `<Entities>` 两个节点）→ `new Project(...)`（Project.cs:42-108）：

1. 遍历 `<Subsystems>` 逐个 `Activator.CreateInstance` + `Initialize`（只构造不 Load）；
2. `InitializeEntities`：每建完一个实体派 `EntityComponentsInitialized`（Entity.cs:128）；组件排序按模板 `LoadOrder`，mod 组件（命名空间≠"Game"）+10000 强制排到原版之后（Entity.cs:122-124）；
3. `AddEntities` → `BeforeSubsystemsAndEntitiesLoad?.Invoke`（Project.cs:84-86）；
4. `LoadSubsystem` 按 `Dependencies` 递归调 `Subsystem.Load`（Project.cs:88, :358-386；递归>100 层抛）；
5. `LoadEntities` 调各组件 `Load`（Project.cs:90；组件 Load 在 Entity.cs:206-215，**异常包成 `Error loading component 全名.`**）；
6. `OnProjectLoad?.Invoke`（Project.cs:91）→ 钩子 `OnProjectLoaded`。

组件 `Class` 类型未知时：`IsOptional=true` → 静默消失；false → 抛、整个世界进不去（Entity.cs 读取分支）。模板里已不存在的组件状态袋成"孤儿袋"被静默丢掉。

### 保存全链

触发：窗口失焦/离开 GameScreen/**每 300 真实秒**/手动保存。链路（GameManager.cs:118-157）：`m_project.Save()`（**游戏线程**，Project.cs:284-297：逐 `Subsystem.Save(valuesDictionary)`，`Count > 0` 才写进项目袋 :290-292；实体侧 `InternalSaveEntity` 同款 `Count > 0` 判断，Entity.cs:217-225）→ 等上次写盘 → `Task.Run` 转**线程池线程** → `Project.bak` = 上次 Project.xml（WorldsManager.cs:103-109）→ 派 `ProjectXmlSave` 钩子（参数是**空** `<Project>`，GameManager.cs:139-143）→ `ProjectData.Save(xElement)` 填 `<Subsystems>/<Entities>`（ProjectData.cs:56-65）→ 写 `Version`(SerializationVersion)/`APIVersion` 属性（:145-146）→ 派 `OnProjectXmlSaved` 钩子（改 XML 的最后时机）→ UTF-8 写盘。第 4 步起任何钩子抛异常 = "无法保存"对话框且**文件不写**。

### 组件丢失条件：Count>0 才落盘

某次 `Save` 一个值都没写 → 读档时该组件/子系统**整个子字典不存在** → `Load` 必须给默认值（`GetValue(key, default)`）。同理删模组后：实体模板找不到整个 `<Entity>` 被丢（仅警告 `Ignoring invalid entity`）；组件 Class 未知按 IsOptional 分崩/静默。

### 旧档兼容

- 版本属性：根上 `Version`=`VersionsManager.SerializationVersion`（主.次）、`APIVersion`=`ModsManager.APIVersionString`；不匹配走 `VersionConverter` 链逐级转换，**找不到路径抛** `Cannot find conversion path...`（VersionsManager.cs）；转换器只从游戏程序集反射收集——模组加 VersionConverter 子类不生效，兼容逻辑写在组件 Load 里（按 object 取出再分支转型）。
- `BlocksManager.LoadBlocksStaticly = string.IsNullOrEmpty(worldInfo.APIVersion)`：区分"纯原版档"与"带模组档"的方块表加载方式。
- `NonPersistentMod=true` 唯一作用：写 `UsedMods` 清单时跳过（SubsystemUsedMods.cs:14-16）；回读时未安装/版本不够给警告框但**可硬闯**（PlayScreen.cs:187-274）；`CompareModVersion` 默认 `=> true`，不重写永远无版本警告。
- 损坏自动回滚：`RepairWorldIfNeeded` 先试 Project.xml，不行用 Project.bak，再不行用内置 `RecoveryProject` 现造（WorldsManager.cs:65-95）。
- 存档读取用 `TypeCache.FindType(name, false, true)`（连系统程序集一起扫）；模组自定义类型在 `Type=` 里必须写全名（`Game.MyData`）。

### 跨实体引用与注意事项

`IdToEntityMap` 是空壳且世界加载路径传 null；引用别的实体用 `EntityReference`（`id:…`/`name:…`，靠 Entity.Id 在重载间存活）。组件/子系统 Load 抛异常直接崩世界（`Loading World Failed!`）；`EntityComponentsInitialized` 与 `BeforeSubsystemsAndEntitiesLoad` 是静态事件且 Dispose 不清 → **同进程第 N 次进世界派发 N 次**，钩子里要去重。

### 值级编解码双轨制：HumanReadableConverter 活轨 vs Archive 契约闲置轨

SC 存档的值编解码**不走** Archive 体系：`XmlInputArchive/XmlOutputArchive/BinaryInputArchive/BinaryOutputArchive/ISerializer` 在整个代码库除 Engine.Serialization 自身外**零引用**，`ISerializable` 无任何实现者——整套契约/对象图/二进制存档是引擎通用层的闲置基建。真正路径：`XmlUtils.SetAttributeValue`/`GetAttributeValue` → `HumanReadableConverter.ConvertToString/ConvertFromString`（XmlUtils.cs:37-46/:19-30）→ 各 `*HumanReadableConverter` 转换器。

HRC 注册与派发（HumanReadableConverter.cs）：转换器类挂 `[HumanReadableConverter(typeof(T))]`，`ScanAssembliesForConverters` 启动时扫**所有非系统程序集**（:118-140，只排除 `IsKnownSystemAssembly`，模组程序集参与扫描）；先扫到先注册（:128）；精确未命中按 `IsSubclassOf` 回退（:100-105，Enum 转换器靠它接住所有枚举）；`Nullable<T>` 解包到底层类型（:27-38）；null 值写出为空串（:11-13）。

### 存档值 XML 编码格式与读回规则

落盘（ValuesDictionary.Save，ValuesDictionary.cs:91-105）：嵌套袋→`<Values Name="k">` 递归；标量→`<Value Name="k" Type="短类型名" Value="HRC串"/>`。`Type` 属性= `TypeCache.GetShortTypeName`（TypeCache.cs:113-114）：基元写短名（float→"float"、int→"int"、bool→"bool"、string→"string"），自定义/游戏类型写全名（Survivalcraft\Content\Assets\Database.xml 实例：`Type="float"` ×826、`Type="Game.CreatureCategory"` ×52，另有少量手写 `Type="System.Double"` 也能解析）。

主要值格式：bool→`True/False`（BooleanHumanReadableConverter.cs:4-6）；float/double/decimal→`"R"` 往返格式不变量文化（SingleHumanReadableConverter.cs:5-8 等）；DateTime→Ticks 整数（DateTimeHumanReadableConverter.cs:5-8）；Guid→"D"（GuidHumanReadableConverter.cs:4-7）；Color→`R,G,B`（A=255）或 `R,G,B,A`，读侧另支持 `#RRGGBB`/`#RRGGBBAA`（ColorHumanReadableConverter.cs:7-29）；Vector2→`x,y`（单值 `"0.5"` 合法自动展开，Vector2HumanReadableConverter.cs:15-20）；枚举→名称（**区分大小写**，EnumHumanReadableConverter.cs:7）。

读回（ValuesDictionary.ApplyOverrides(XElement)，ValuesDictionary.cs:146-184）：`Type` 缺失→沿用袋内现值类型（:154-158）；`Type` 未知→`FindType(...,false)` 得 null→**静默 continue 跳过该值**（:161-164）——删模组后自定义类型值无声消失的底层原因；`overrideExistOnly=true` 时新键丢弃（:150-151）。`XmlUtils.GetAttributeValue` 解析抛任何异常→**静默返回 defaultValue 不上抛**（XmlUtils.cs:22-27）——与 ValuesDictionary.GetValue 硬拆箱必抛是两套错误策略：袋内类型不符会崩，XML 字符串解析失败只会悄悄回默认。

### 类型名解析（TypeCache）

短名↔全名固定表 30 项（TypeCache.cs:33-62）：13 个基元 + Vector2/3/4、Quaternion、Matrix、Color、Point2/3、Rectangle、Box、BoundingRectangle/BoundingBox/BoundingCircle/BoundingSphere、Plane、Ray2/3；`GetShortTypeName`/`GetLongTypeName` 未命中回退原名（:113-117）。`FindType` 全程序集线性扫+按原始字符串缓存（:87-111）：存档读用 `throwIfNotFound=false`（得 null 静默），Archive 对象图 `_type` 用 `true`（抛 `Type "..." not found in any loaded assembly.`）。系统程序集判定=FullName 小写含 4 个 .NET 公钥 token 或 openTK/sharpdx/silk（:70-85）。`AssemblyLoad` 事件置 `m_rescanAssemblies`→下次访问自动重扫（:63-67）——新加载的模组程序集无需重启即可被 FindType 找到，但已缓存条目不清。

### Archive 契约体系（引擎通用层）与版本兼容补充

契约发现（Archive.cs）：每类型一份 `SerializeData` 缓存（Read/Write 委托+UseObjectInfo+AutoConstruct+构造器，:24-101）；`GetSerializeData` 派生顺序：实现 `ISerializable` → 数组→`ArraySerializer<>` → 枚举→`Enum32/64Serializer`（底层类型仅 int/uint/long/ulong，否则抛 :262-273）→ 泛型容器（扫描期登记 :242-246）→ 基类契约克隆（AutoConstruct 补 Yes，:280-289）→ 空壳（不可序列化）。实例化：构造器沿基类链找（含非公开，:88-100），找不到就 `RuntimeHelpers.GetUninitializedObject` 跳过构造器（:81-85）。

对象图（`UseObjectInfos=true` 默认开，Archive.cs:115）：写侧首次出现记 `_def`=objectId、再遇写 `_ref`（OutputArchive.cs:74-95）；读侧 `m_objectById` 重建共享引用（InputArchive.cs:165-172/:193-195），循环引用安全；`FindParentObject<T>` 沿序列化栈上溯（InputArchive.cs:108-118）。XML 轨浮点 "R"（XmlOutputArchive.cs:53-59）、byte[]→Base64（:78-87）、string 键字典键→`XmlConvert.EncodeLocalName` 元素名（:117）、`RemoveUnusedDefs` 清悬空 `_def`（:186-211）。二进制轨：7bit 变长 int/长度（BinaryOutputArchive.cs:44-51）、字符串驻留表首现写本体后续只写 id（:81-94，读侧 BinaryInputArchive.cs:72-84）、对象头位标志（偶=引用/奇=新对象、bit1=有 id、bit2=跟类型全名、id 在高 4 位，BinaryInputArchive.cs:141-155 / BinaryOutputArchive.cs:136-155）。`Archive.Version/Context` 构造参数（Archive.cs:113-115）供序列化器做版本分支——当前无人使用。

版本兼容补充（与上文"旧档兼容"互参）：`SerializationVersion`=游戏程序集版本的主.次（VersionsManager.cs:54-55，非手写常量）；VersionConverter 只从游戏程序集反射收集（:52，:57-67）；`FindTransform` 最短路径图搜索+100 层防环（:132-159）；`UpgradeProjectXml` 转换后二次校验 Version 属性，不对抛 `Upgrade produced invalid project version`（:86-91）。

## 坑与对策

- **`InvalidCastException: Unable to cast Single to Int32`（读档崩）**：写入类型与 `GetValue<T>` 泛型不同袋键 → 统一类型；修完按 object 读取兼容旧档。XML 里的 `Type="Single"` 不参与转换，`GetValue<T>` 只硬拆箱。
- **`Error loading component XxxComponent`**：该组件 Load 抛异常 → 看内层异常；多为上一条类型拆箱或键缺失。
- **Save 里读不到上次存档值**：Save 的参数是**新空袋**（Entity.cs:218-220），要从 `this.ValuesDictionary` 读。
- **改了值没存上**：该次 Save 没写任何键（Count=0）整个子字典不落盘；或 Save 忘调 `base.Save/Load` 漏父类字段。
- **删模组后"方块变空气/生物消失"**：模板或组件 Class 没了 → 模板 GUID 保留 + IsOptional 设计决定崩档还是静默。
- **在 ProjectXmlSave 加顶层 `<Subsystems>`/`<Entities>` 元素**：ProjectData.Save 用 FindChildElement 取**文档顺序第一个**同名节点 → 你的会被引擎当正主、引擎那份被无视 → 数据丢失。
- **保存钩子碰 UI/非线程安全对象**：第 4-9 步在线程池线程 → 必须 `Dispatcher.Dispatch` 包裹。
- **模组设置≠存档**：所有模组设置合在全局 `ModSettings.xml`，换存档不变 → 每世界数据走 Subsystem.Save。
- **Reboot 后旧 Type 仍在跑**：程序集不可卸载、TypeCache 缓存不清 → 验证新代码必须重启进程。
- **sbyte 进存档抛 `IHumanReadableConverter for type System.SByte not found`**：sbyte 是唯一没有 HRC 转换器的基元（Engine.Serialization 目录无 SByteHumanReadableConverter.cs）→ 改用 byte/int。
- **枚举值大小写敏感**：`Enum.Parse(type, data, false)`（EnumHumanReadableConverter.cs:7）→ 手改存档/模板里枚举字符串大小写错直接抛。
- **值解析失败静默回默认**：`XmlUtils.GetAttributeValue` 捕获一切异常返 defaultValue（XmlUtils.cs:22-27）→ `Value="abc" Type="int"` 不报错、悄悄回默认；数据"莫名不对"先查这里。
- **char 值空串抛 IndexOutOfRange**：`data[0]` 无保护（CharHumanReadableConverter.cs:7）。
- **模组 HRC 注册先到先得**：注册扫描只排除系统程序集且 `ContainsKey` 防重复（HumanReadableConverter.cs:119/:128）→ 与游戏或其他模组同名类型时，注册结果取决于程序集加载顺序，不可控。
- **string 键字典存 XML 后键被编码**：string 键经 `XmlConvert.EncodeLocalName` 变元素名（XmlOutputArchive.cs:117，Archive 轨）→ 特殊字符键手改存档对不上。
- **bool 的 XML 文本只认 True/False**（Archive 轨 XmlInputArchive.cs:79-91，OrdinalIgnoreCase）→ "1"/"0" 抛 `Cannot convert string to a Boolean`。
