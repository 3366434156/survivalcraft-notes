## 一句话定位

挖掘就是一条除法：**挖穿时间 = 方块 DigResilience ÷ (工具对应家族 Power × 玩家 DigSpeedFactor)**，工具的全部作用是把这个除数变大；"层级"分两套互不相干的数——工具的 `ToolLevel` 只决定挖掉后**给不给掉落**（对上被挖方块的 `RequiredToolLevel`），工具/方块上另一套 `PlayerLevelRequired` 只决定**敢不敢让你手持使用**；耐久不进 ValuesDictionary，直接编码在物品值的 data 位里随槽走。

## 1 挖掘进度公式

### 1.1 全式（生存/危险模式，CalculateDigTime :1277-1291）

```
挖穿时间 = DigResilience(被挖方块) / ( Power × DigSpeedFactor )
Power    = 按 被挖方块.DigMethod 三选一取手持物: Shovel → ShovelPower / Quarry → QuarryPower / Hack → HackPower
DigSpeedFactor = StrengthFactor × OtherFactorsResults["DigSpeed"]          (ComponentMiner.cs:98-109)
若 Power × DigSpeedFactor ≤ 0 → 时间 = ∞（永远挖不动）                      (:1288-1290)
```

出处：`ComponentMiner.CalculateDigTime`（ComponentMiner.cs:1241-1292）；Dig 入口取 `digTimeWithActiveTool` 后 `m_digProgress = saturate((GameTime − m_digStartTime) / digTime)`，时间 0 视为进度 1（:212-215）。换目标格即重置起点（:205-211）。

### 1.2 各因子出处

| 因子 | 从哪读 | 默认 | 出处 |
|---|---|---|---|
| DigResilience | 被挖方块值 → `GetDigResilience`，实际值在 BlocksData.txt `DigResilience` 列 | 1（Block.cs:137） | Block.cs:306；BlocksData.txt:1(表头) |
| DigMethod | 被挖方块值 → `GetBlockDigMethod`，枚举 None/Shovel/Quarry/Hack | None | Block.cs:308；Game/BlockDigMethod.cs:2-8 |
| Shovel/Quarry/HackPower | **手持物** → `GetShovelPower/GetQuarryPower/GetHackPower`，BlocksData 同名列 | 各 1（Block.cs:117-121） | Block.cs:310-314 |
| StrengthFactor | `ComponentFactors`（玩家实体上是子类 ComponentLevel）每帧由 `m_strengthFactors` 加/乘合成 | 1 | ComponentFactors.cs:64-68/:199-214 |
| DigSpeed 因子 | `ComponentFactors.OtherFactors["DigSpeed"]`（模组可 Add 自定义 Factor；Load 时注册三个键 AttackSpeed/DigSpeed/ChaseRange） | 空表=1 | ComponentFactors.cs:18-20/:99-100 |
| 徒手 | 手持值 0 → `Blocks[0]`(空气) 各 Power 取字段默认 1 | 1 | ComponentMiner.cs:1242/:310-314 |

StrengthFactor 的玩家配方（ComponentLevel.GenerateStrengthFactors，ComponentLevel.cs:141-163）：性别女 ×0.8（:73）、等级 `1+0.05×floor(clamp(等级,1,21)−1)`（:146-148，满级 ×2.0）、体力 `lerp(0.5,1,sat(4×体力))×lerp(0.9,1,sat(体力))`（:149-151，0.45~1）、生病 ×0.75（:152）、**呕吐中 ×0 → 整个除数 0 → 挖不动**（:154-155，咳嗽同理 :158-159）、流感 ×0.75（:156）、无害模式 ×1.25（:160）。挖掘是否吃力量加成由 `m_digSpeedBasedOnStrengthFactor`（默认 true）总开关控制（ComponentMiner.cs:96/:100-103）。

### 1.3 三模式差异（CalculateDigTime 内部分支）

| 模式 | 规则 | 出处 |
|---|---|---|
| 创造 | Resilience<∞ → 时间 0（瞬挖）；∞（基岩）→ ∞ | ComponentMiner.cs:1249-1254 |
| 冒险 | 要求**匹配家族且 Power≥2**，否则 ∞；`时间 = Resilience / (Power × StrengthFactor)`（不吃 DigSpeed 自定义因子） | :1256-1275 |
| 生存/危险 | §1.1 全式，无门槛——**任何 Power>0 的工具都能挖任何 Resilience 有限的方块**，工具只影响快慢 | :1277-1291 |

徒手：Power 全 1 → 时间 = Resilience / DigSpeedFactor。花岗岩 Resilience 14（BlocksData.txt:9）→ 徒手 14s、铁镐 14/13≈1.1s、钻石镐 14/15≈0.9s；泥土 1.5（:6）→ 徒手 1.5s。基岩 Resilience=∞（:5）→ 谁都挖不动。

### 1.4 挖掘循环与提示

- 挥动动画相位 `PokingPhase` 每游戏秒 +4（创造 1/CreativeDigTime），跨 0.5 时结算一次（ComponentMiner.cs:1152-1160/:267）。
- 创造+桌面输入 → 直接即时完成（:231-233）。
- 工具提示：生存且 `digTime≥3s` 且进度>0.5 时，若"背包有更快的工具（<0.5×当前时间）"或"徒手等速" → 小字提示，冷却 300 真实秒（:242-266，冷却判据 :246，Time 为秒制 Engine/Engine/Time.cs:44-46）。
- 进度满 → `GetDigValue`（默认写 0=销毁，Block.cs:413-422）→ `DestroyCell(手持物.GetToolLevel, …)`（ComponentMiner.cs:273-282）。

## 2 工具层级与"能挖什么"

### 2.1 两套"层级"必须分清

| 数 | 挂在谁身上 | 数值源 | 检查点 | 不达标后果 |
|---|---|---|---|---|
| `ToolLevel` | **工具/物品**（石斧2·铜/铁3·钻4·木棒1，BlocksData `ToolLevel` 列） | Block.cs:129/:260 | 挖掉时作为 toolLevel 传入 DestroyCell → `GetDropValues` 里与被挖方块的 `RequiredToolLevel` 比较（Block.cs:433-435） | **照样挖掉，只是不掉落** |
| `RequiredToolLevel` | **被挖方块**（全表仅 9 行设了：雪 1、叶族 6 种 1、南瓜灯 1、草套陷阱 3） | Block.cs:93/:424 | 同上 | 无掉落（Block.cs:433-435） |
| `PlayerLevelRequired` | **手持物**（默认 1，Block.cs:131） | Block.cs:131/:231 | `IsLevelSufficientForTool`：非创造且开"冒险生存机制"时，玩家等级 < 手持物要求 → 拒用（挖/放/打/用全拦，ComponentMiner.cs:1294-1316/:216-230） | 手持物完全不能用，提示所需等级 |

关键结论：**原版没有 MC 式"石头必须镐"门槛**——花岗岩 `RequiredToolLevel=0`（BlocksData.txt:9），徒手慢挖照样掉圆石；层级门只用在叶族（OakLeavesBlock 数据行 :46，徒手挖叶 ToolLevel 0<1 → 无掉落）和草套陷阱（GrassTrapBlock=3，数据行 :125）。爆炸调 `GetDropValues(toolLevel=0)`（Subsystem/SubsystemExplosions.cs:689）→ RequiredToolLevel>0 的方块炸了必不掉。

### 2.2 DigMethod 三族与家族匹配

`DigMethod` 是**被挖方块**的属性（工具不设此列）：Shovel=铲族（泥土/草/沙）、Quarry=镐族（石族）、Hack=斧族（木族/叶）。匹配 = 挖掘时取工具那个家族的 Power。工具三 Power 都有值，错族工具只剩非主力 Power（如镐的 ShovelPower 1.5≈徒手稍强）。

### 2.3 自定义"可挖判定"的四个挂点

1. 要"必须 X 级工具才有产出" → 方块 `RequiredToolLevel` + 工具 `ToolLevel`（数据两列）。
2. 要"完全挖不动" → 方块 `DigResilience=Infinity`（基岩范式）或把工具该族 Power 设 0。
3. 拦等级校验 → 钩子 `IsLevelSufficientForTool(this, toolValue, ref canUse, out skip)`（ComponentMiner.cs:1296-1306，skip=true 即 mod 说了算）。
4. 拦挖掘进度 → 钩子 `OnMinerDig`（:234-241，见 §5）。

## 3 耐久与消耗

### 3.1 耐久存哪

**存物品值 data 位**：`GetDamage = (data >> 4) & 0xFFF`（0..4095），`SetDamage` 原位写回（Block.cs:457-464，上限 clamp 4095）。耐久上限是类字段 `Durability`（默认 −1=不可损，Block.cs:133/:489），工具值由 BlocksData `Durability` 列给。不占 ValuesDictionary、不占槽位额外存储——**换槽/丢地/捡回耐久随值走**。特例自编码：弓 `(data>>8)&0xFF`（BowBlock.cs:103）、弩/火枪同式（CrossbowBlock.cs:119、MusketBlock.cs:100）、衣物 `(data>>8)&0xF`（ClothingBlock.cs:160）。

### 3.2 扣减点（每次 1 点，钩子可改）

| 动作 | 扣减 | 出处 |
|---|---|---|
| 挖掉一格 | `DamageActiveTool(1)`，钩子 `OnBlockDug` 改 `ref durabilityReduction` | ComponentMiner.cs:283-298 |
| 近战**命中**一次 | `DamageActiveTool(1)`，钩子 `OnMinerHit2` 改 | :678-688 |
| 挥空/未命中 | 不扣 | :689-705（miss 分支无 Damage） |

`DamageActiveTool` 创造模式直接返回（:1089-1093）；否则 `BlocksManager.DamageItem(值, 扣数, 实体)`（:1094）。

### 3.3 断裂结算（BlocksManager.DamageItem :1011-1035）

```
Durability < 0      → 原值返回（不损耗）
GetDamage + 扣数 ≤ Durability → SetDamage 新值替换槽内物品（耐久刻进 data）
GetDamage + 扣数 > Durability → GetDamageDestructionValue(value)：
        默认 0 → 槽内移除 1 个 = 工具直接消失（Block.cs:466）
        覆写：食物→腐坏值（FoodBlock.cs:60）、鸡蛋→246（EggBlock.cs:143）、奶桶→245、油漆桶→90
```

钩子 `DamageItem(block, value, damageCount, owner, out skipVanilla)` 可整段接管（BlocksManager.cs:1016-1025）。挖坏手持非工具方块（Durability −1）= 原值返回，无消耗。

### 3.4 展示与攻击侧数值（附）

- 背包槽血条：`(Durability − GetDamage) / Durability`（`GetBlockHealth` Block.cs:480-487 → InventorySlotWidget.cs:361-370）。
- 近战伤害 = `手持物.GetMeleePower × AttackPower(实体模板) × rand(0.8,1.2) × StrengthFactor`（ComponentMiner.cs:641-642/:676）；徒手 = `AttackPower × rand`（:646）。玩家模板 AttackPower=1（Database.xml FemalePlayer/MalePlayer；牛1/公牛1.75/熊3.5）。命中率 `GetMeleeHitProbability`（默认 0.66，Block.cs:125/:474；斧 0.5、木棒 0.7），目标近静止（速度<0.05）×2（:649）；玩家掷命中率、AI 生物固定 `num3`（默认 1）。
- 攻击间隔 = 模板 `HitInterval`(玩家 0.66s，Database.xml:4090，ComponentMiner.Load :1207 载入) ÷ `OtherFactors["AttackSpeed"]`（ComponentMiner.cs:62-66/:589-596，钩子 `SetHitInterval`）。

## 4 挖掘产出

### 4.1 默认 GetDropValues（Block.cs:426-455）

1. `toolLevel < RequiredToolLevel` → 空表返回（:433-435）。
2. `DefaultDropContent` 掉 `floor(DefaultDropCount)` 个 + 小数部分按概率 +1（:437-446，逐个入表）。
3. `DefaultExperienceCount` → 逐个掉经验球 248（:447-454）→ 拾取加进 `PlayerData.Level`（ComponentLevel.cs:114），死亡减半（Game/PlayerData.cs:301-303）——等级回流 §1.2 的力量因子，闭环。
4. 调用方 `SubsystemTerrain.DestroyCell`：掉落逐项过方块行为 `OnItemHarvested` → `SubsystemPickables.AddPickable`（Subsystem/SubsystemTerrain.cs:442-459）。创造选取方块取掉落时传 `toolLevel=int.MaxValue` 强制全掉（ComponentPlayer.cs:543）。

### 4.2 覆写范例

| 方块 | 行为 | 出处 |
|---|---|---|
| 砾石 | 33% 走默认（掉自身），67% 掉 1-3 燧石 79 | GravelBlock.cs:10-29 |
| 常青叶 | 25% 掉树苗 23，否则走基类 | EvergreenLeavesBlock.cs:9-21 |
| 落叶族 GetDigValue | 秋季后半"摇树"→ 只换冬季 data 不销毁（GetDigValue 返回值=格子新值） | DeciduousLeavesBlock.cs:148-164 |

### 4.3 有没有 silk-touch 类机制

**没有**。全仓 `GetDigValue` 覆写仅 2 处（落叶摇树、WireBlock），不存在"持特定工具改变掉落/保留方块"的原版机制；掉落只认 `GetDropValues(toolLevel)`。mod 想做等价物：覆写 `GetDigValue` 让格子保留（照抄 DeciduousLeavesBlock 范式）或在 `GetDropValues` 里读 `componentMiner` 不可行——签名没有工具值，但 `GetDigValue` 有 `toolValue` 参数（Block.cs:413-417）。[推测] 也可在 `OnItemHarvested` 方块行为里按场景改 dropValue。

## 5 mod 视角：自定义工具最小集

| 步骤 | 必写 | 照抄 |
|---|---|---|
| 1 类 | `class X镐Block : PickaxeBlock { public static int Index=N; public X镐Block() : base(手柄纹理槽, 头纹理槽) {} }`——基类 Initialize 自动烘 `Models/Pickaxe` 双部件（Shovel/Axe 同理换模型名） | CopperAxeBlock.cs 全文 7 行；IronPickaxeBlock.cs:5 |
| 2 数据 | mod 包内 **`.csv`**（扩展名小写敏感）加一行，表头抄 BlocksData.txt:1，按列名反射赋值 | BlocksManager.LoadBlocksData BlocksManager.cs:1037-1094；mod 装载 ModEntity.cs:303-315（BlocksManager.cs:410 触发） |
| 3 关键列 | `MaxStacking=1`、三 `Power` 列、`ToolLevel`、`Durability`、`DefaultMeleePower`(+`DefaultMeleeHitProbability`)、`DigMethod` 留空（工具不是被挖物）、纹理槽 `DefaultTextureSlot` | IronPickaxe 行 BlocksData.txt:175 |
| 4 攻击/挖速全局 | `OtherFactors["DigSpeed"/"AttackSpeed"].Add(new Factor{Value=…})` 或 `m_strengthFactors`——注意每帧被 Generate 清空，须在 `OnFactorsUpdate` 钩子里填（ComponentFactors.cs:199-214） | ComponentFactors.cs:46-62 |
| 5 门槛（可选） | 方块 csv `RequiredToolLevel` + 工具 `ToolLevel`；或工具 `PlayerLevelRequired`+冒险机制 | §2.1 表 |

分工：**数值全在 csv，代码只管外形**——三族工具类的差异=ctor 两个纹理槽，其余由数据行决定；注册走 Block 子类自动发现（需 `public static int Index`）。最短范例判定：要现成模型抄 `CopperAxeBlock.cs`（7 行）；要完全自定义外形抄 `WoodenClubBlock.cs`（直接 : Block，单部件自烘，WoodenClubBlock.cs:5-25）。
