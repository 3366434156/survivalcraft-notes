## 核心机制

### 1. 玩家会话层：PlayerData 不是实体，是出生状态机

- 玩家在存档里的持久数据由 `PlayerData` 持有（名字/职业/等级/皮肤/出生点/次数），Load/Save 键列表 `PlayerData.cs:376-398`；持久化宿主是 SubsystemPlayers：每玩家一个子 ValuesDictionary（`Subsystem\SubsystemPlayers.cs:93-114`）。
- 运行期由 5 态 StateMachine 驱动：FirstUpdate → PrepareSpawn → WaitForTerrain → Playing ⇄ PlayerDead，全部注册于构造函数 `PlayerData.cs:142-343`。
- 出生点评分：初次出生 61×61 网格打分（海拔 64-85 加分、季节温度<8 减分、面海射线、头顶遮挡减分）`ScoreIntroSpawnPosition PlayerData.cs:458-500`；重生 17³ 立方打分（脚下实心、自身两格非碰撞、离其他玩家远）`PlayerData.cs:502-533`。
- 等地形两阶段各最多 15 秒，超时照样出生（`PlayerData.cs:240-241`、`TerrainMaxWaitTime PlayerData.cs:37`）。
- `SpawnPlayer`（`PlayerData.cs:553-665`）：出生在水上先造 Boat 实体并骑乘（:559-567）；非重生时按皮肤×性别硬编码四件默认衣物（:573-629）；初始物品只有 Slot1=方块162×1，且仅非创造模式给 1 个（:630,642）；实体模板按性别取 `MalePlayer`/`FemalePlayer`（:647）。
- 死亡降级：`ReduceLevelUponDeath` 时等级减半下取整（:301-303）；残忍模式死亡只能弹 GameMenuDialog、冒险模式不允许重生则整屏切 AdventureRestart（:325-331）。
- 每帧语义输入是纯数据 struct `PlayerInput`（Look/Move/Jump/Dig/Hit/Aim/Interact/Drop/SelectInventorySlot 等 24 字段 + `ValuesDictionaryForMods` 扩展袋，`PlayerInput.cs:5-73`），由组件层每 tick 填充后消费。
- 统计 `PlayerStats`：全部计数器打 `[Stat]` 特性，Load/Save 靠反射遍历（`PlayerStats.cs:135-143,157-185`）；死亡记录 DeathRecord 序列化成 `日,x,y,z,原因` 分号拼接字符串（:38-50,174-180）。
- mod 钩子四处：`PlayerDataFirstUpdate`（:153）、`OnPlayerDead`（:294）、`UpdateDeathCameraWidget`（:312）、`OnPlayerSpawned`（:657）。
- 引擎内**不存在**成就（Achievements）系统：全源码 grep 零命中；"成长"只体现为 Level 与 `PlayerStats`。

### 2. 库存槽位模型：一个接口管所有容器

- 契约是 `IInventory`（`IInventory.cs:5-30`）10 成员：SlotsCount/VisibleSlotsCount/ActiveSlotIndex + 每槽 Get{Value,Count,Capacity,ProcessCapacity} + AddSlotItems/ProcessSlotItems/RemoveSlotItems/DropAllItems。背包、合成表、创造目录、家具格、熔炉全部实现它（实现类在实体组件层，逐行见 03a 页 InventoryBase 链）。
- 槽位容量不是全局常量：`GetSlotCapacity(slot,value)` 按"槽+物品"二元组回答，UI 与投放逻辑一律先问容量。
- **功能区槽位放尾部**是全库约定：熔炉末三格=燃料/产物/余渣（`SlotsCount-3/-2/-1`，ComponentFurnace.cs:62-66），工作台末两格=产物/余渣——自定义容器照此排布。
- 创造背包 = 一只大 IInventory：槽 0-9 是玩家手部格，槽 10+ 是全物品目录；面板按 `Block.GetCategory` 字符串过滤槽下标再分页（`CreativeInventoryPanel.cs:54-75`），翻页只是改"槽下标列表的窗口"（:76-90），不搬物品。
- 家具背包面板管理"家具设计集合"：格子里只显示 contents=227（家具方块）且属于当前 FurnitureSet 的槽，分页渲染（`FurnitureInventoryPanel.cs:196-225`）；新建/重命名/删除/移动/导入导出 .scfpack 全在此（:227-406），集合数上限 32（:100）。
- 拖拽 = `InventoryDragData`（IInventory+槽号+DragMode 三字段，`InventoryDragData.cs:2-8`）挂在 Widget 层传递。
- `ScannedItemData`（`ScannedItemData.cs:4-18`）是"从某容器扫出来的一项"（Container/IndexInContainer/Value/Count），物品扫描器与拾取逻辑的数据总线。

### 3. 伤害结算链：Attackment 一条流水线

- 入口 `Attackment.ProcessAttackment()`（`Attackment.cs:213-263`）：友伤开关检查 → `ProcessAttackment` mod 钩子 → 分发目标有 ComponentHealth 走生物流程、有 ComponentDamage 走非生物流程 → 冲量+眩晕。
- 伤害折减 `CalculateInjuryAmount()`（`Attackment.cs:82-111`）：AttackPower → 目标衣物 `ApplyArmorProtection` → `ComponentFactors.ResilienceFactor` 除法 → `ComponentHealth.AttackResilience`（生物）或 `ComponentDamage.AttackResilience`（非生物）再除一次，返回负数表示不可伤。
- 护甲单件吸收公式 `ClothingData.ApplyArmorProtection`（`ClothingData.cs:122-167`）：`吸收=min(剩余攻击力×saturate(ArmorProtection/attackment.ArmorProtectionDivision), 剩余Sturdiness)`；非创造模式按吸收比例扣衣物耐久（:138-141），打碎出碎屑粒子；`ArmorProtectionDivision` 是给 mod 护甲留的除数（`Attackment.cs:66-71`）。
- 近战冲量按质量比缩放：`ImpulseFactor=5.5×saturate((攻质量/受质量)^0.5×(攻击力≥2?1.25:1))`，眩晕 0.25s×同系数（`MeleeAttackment.cs:13-19`）；弹射物固定 ImpulseFactor=2、零伤不冲不晕（`ProjectileAttackment.cs:16-20`）。
- 伤害类型族：`Injury` 基类（含友好火伤/攻击伤子类于 `TypedInjury.cs:2-57`），`IInjurable.cs` 是可受伤接口；飘字 `HitValueParticleSystem` 玩家造成且>0 才白色显示（`Attackment.cs:113-135`）。
- 注意：类名 Attackment 拼写是历史错误，注释明说不许改名（`Attackment.cs:7-11`）。

### 4. 掉落物：Pickable 是"不是实体的实体"

- `WorldItem` 基类只有 10 个字段：Value/Position/Velocity/CreationTime/Light/ToRemove/Creator/IsFireProof/MaxTimeExist/ExplosionMass + mod 数据袋（`WorldItem.cs:5-35`）；Pickable（掉落物）与 Projectile（弹射物，→13页）都是它的子类，由各自 Subsystem 用普通列表管理，不走实体系统。
- 自动消失寿命与"场上现存掉落物数量"挂钩（`Pickable.cs:174-196`）：Terrain 类和无营养植物类 >80 个时 60s、否则 120s；其他方块 >80 时 120s、否则 480s；蛋固定 240s；`MaxTimeExist` 可覆盖。
- 移动每帧手写：重力 -10、空气阻力 0.5^dt、流体按方块密度浮力+流速、命中面反弹系数按速度分流（`Pickable.cs:198-424`）；卡进方块时 7³ 搜最近空位飞过去（:262-292）。
- StuckMatrix（钉在方块上，箭/工具）每帧验证支撑还在，没了就掉落（:315-329）。
- 火/岩浆连锁：站在火格或岩浆上 → 播放嘶声 → `TryExplodeBlock`（易爆物品被"烧爆"而非烧毁）（:330-405）。
- 爆炸波及 `UnderExplosion`：伤害/爆炸韧性 >0.1 直接连锁爆炸；否则冲量够大就转成 Projectile 飞出去，33% 概率挂烟尾（:441-476）。
- 存档多态：Save 写入 `Class=GetType().FullName`，读回按类名实例化（:548-562）。

### 5. 合成匹配链

- 配方数据 `CraftingRecipe`：9 格 string 配料阵 + Result/Remains（容器返还）+ RequiredHeatLevel/RequiredPlayerLevel + DisplayOrder（`CraftingRecipe.cs:2-27`）；配料串是 `方块名[:data]`，解码走 `DecodeResult`/`DecodeIngredient`（均带同名 mod 钩子）。
- 匹配在 `Managers\CraftingRecipesManager.cs`：`FindMatchingRecipe`(:141) 先遍历 256 方块问 `GetAdHocCraftingRecipe`（动态配方，如雕家具），再线性扫静态表；命中后查热量/等级，不足时**返回一个只带 Message 的假配方**用于 UI 提示。
- `MatchRecipe`(:220) 对 9×9 残阵做镜像 + 平移穷举对齐，所以配方与摆放位置无关、允许镜像。
- 注册窗口：`CraftingRecipesManager.Initialize`(:18) 前后各一个 mod 钩子（CraftingRecipesManagerInitialize/Initialized）。
- 工作台 UI 侧 `Widget\CraftingTableWidget.cs` 持 3×3 网格，产物格=SlotsCount-2（详见 03a 页）。

### 6. 世界设置流转

- 单例持有者是 SubsystemGameInfo：Load 时 `WorldSettings.Load`（`Subsystem\SubsystemGameInfo.cs:80-81`），Save 时全量落盘（:88）；季节推进直接改 `WorldSettings.TimeOfYear`（:97-100），即设置对象是"活数据"。
- 双模式保存：游戏模式/天气/季节/重生开关等"运行中可改项"每次都存；种子串/地形生成参数只在 `liveModifiableParametersOnly=false`（建档）时写（`WorldSettings.cs:134-163`）。
- 非创造模式强校验 `ResetOptionsForNonCreativeMode`：Flat 地形降级、环境改 Living、昼夜改 Changing、天气强制开、地形参数回默认（`WorldSettings.cs:64-101`）。
- 世界级信息袋 `WorldInfo`：目录名/大小/最后保存时间/序列化版本/API版本 + 内嵌 WorldSettings + PlayerInfo 列表（`WorldInfo.cs:2-16`）。
- 模式枚举阶梯 GameMode：Creative<Harmless<Survival<Challenging<Cruel<Adventure（`GameMode.cs:2-9`）；多处用 `GameMode <= Survival` 或 `== 0`（创造）判断，顺序是协议。
- 调色板 `WorldPalette`：16 色 + 名字，只存与默认不同的项，空段回落默认（`WorldPalette.cs:65-75`）；颜色名限字母数字-空格 16 字符（:82-95）。

## 坑与对策

- **Attackment 拼写**：类名错拼但被全生态依赖，注释禁止改名（Attackment.cs:7-11）→ 照抄不改。
- **ClothingSlot 重入**：切语言会重调 Initialize，不能 Clear 重建（引用相等作字典键，旧实体会 KeyNotFound）→ 只补缺失部位（ClothingSlot.cs:22-30）。
- **PlayerClass setter 时机**：PlayerData 已加入 PlayersData 后再改职业直接抛异常（PlayerData.cs:89-97）→ 建档前定好。
- **假配方**：FindMatchingRecipe 失败时返回 Message-only 配方而非 null → 调用方必须查 ResultValue 而非只判 null（CraftingRecipesManager.cs:158-168）。
- **掉落物寿命**：>80 个掉落物在场时 Terrain/植物类 60 秒即消失 → 大规模刷物场用 MaxTimeExist 覆盖（Pickable.cs:180-190）。
- **WorldSettings.Save 双参**：运行时用 true 调用不会写种子/地形参数 → 想改种子只能在建档路径（WorldSettings.cs:134-161）。
- **掉落物不是实体**：FindEntity 找不到掉落物 → 走 SubsystemPickables 列表。
