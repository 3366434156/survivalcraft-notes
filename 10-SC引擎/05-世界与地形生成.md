## 核心机制

### 世界初始化流程

```
启动(LoadingScreen.cs 顺序)：
  :467 解析mod设置 → :471 OnLoadingStart → :500-511 .xdb合并 → :531-533 BlocksManager.Initialize
  → :535 CraftingRecipesManager.Initialize → :537-547 WorldsManager 等管理器
进入世界：
  GameManager.LoadProject → 子系统按 .xdb 模板实例化
  → SubsystemBlocksManager.Initialize(:23-28) 二段分配方块ID(按存档类名映射)
  → SubsystemTerrain.Initialize：
      :523 先挂 TerrainSerializer23(唯一存档后端，老格式只被 VersionConverter 读)
      :550-584 再按 WorldSettings.OriginalSerializationVersion 选生成器：
        ≤2.1→TCG21 | 2.2→TCG22 | 2.3→TCG23 | 其余→TCG24 | FlatContinent/FlatIsland→TCGFlat
```

`TerrainGenerationMode` 只有 4 值(Continent/Island/FlatContinent/FlatIsland，TerrainGenerationMode.cs:3-8)。**老存档与平面世界没有步骤列表**，`TerrainContentsGenerator24Initialize` 钩子不触发。TCG24 构造(:280-362)：读 `m_seed`(:176) → 种子派生 4 个噪声域偏移(:290-293) → 填 `TG*` 参数默认值(:294-323) → 注册全部原版步骤(:325-351) → 模组钩子(:352-358) → **最后**才对 4 个步骤列表 `Sort()`(:359-362)。

### 区块模型与存取

- `TerrainChunk`：Size=16、Height=256(:13/:17)；`Cells[Size*Size*Height]`(:61)，线性索引 `y | x<<8 | z<<12`(:138-141)；`Shafts[256]`(:63)存每列温度/湿度/顶底高度/阳光高(:199-237)。`Origin=Coords*16`(:82)。
- value 打包同方块页：contents 低 10 位、light 10-13、data 14+(Terrain.cs:64-72)。
- 存储：`Terrain.m_allChunks` 哈希表，`GetChunkAtCoords`(:155)、`AllocateChunk`(:176)、`FreeChunk`(:195)。

### 区块加载/卸载(AllocateAndFreeChunks，TerrainUpdater.cs:459-515)

- **卸载**：玩家视野圈外(`IsChunkInRange` :447)的区块 → `ToFreeChunks` 钩子(:465-472) → 全部行为 `OnChunkDiscarding`(:478) → `TerrainSerializer.SaveChunk`(:480) → `FreeChunk`(:481)。
- **加载**：范围内缺的 → `AllocateChunk`(:494) + 邻域状态降级(自身降 NotLoaded、8 邻降 InvalidLight，:495-496)。
- 驱动：`Task.Run(ThreadUpdateFunction)` 后台线程(:345/:548)；`SettingsManager.MultithreadedTerrainUpdate=false` 时同步跑(:331-342)；镜头前 6 格的区块在 `PrepareForDrawing`(:392-414) 同步等完。降级接口 `DowngradeChunkNeighborhoodState/DowngradeAllChunksState`(:416-445) 用于运行时改方块后倒回重算。

### 生成管线：十态状态机(UpdateChunkSingleStep，TerrainUpdater.cs:651-810)

```
NotLoaded →[读档成功:653-667→InvalidLight, 标 WasUpgraded]→；[新块]→ InvalidContents1
InvalidContents1/2/3/4 → GenerateChunkContentsPass1..4(:669-701)
  pass4 末尾触发 OnTerrainContentsGenerated 钩子(:702-708)
→ InvalidLight(阳光柱+高度 :716-724, GenerateChunkSunLightAndHeight :812)
→ InvalidPropagatedLight(先等 8 邻推进到同态 :727-736；光源收集 :738-743 含
   GetEmittedLightAmount :901；传播 :748)
→ InvalidVertices1(再等 8 邻 :758-767；GenerateChunkVertices(chunk,0) :772 + 钩子 :773)
→ InvalidVertices2(:788-807, GenerateChunkVertices(chunk,1), NewGeometryData=true)
→ Valid
```

内容四趟**不等邻居**；光照/顶点两阶段才等(:727-736/:758-767)。`NotifyBlockBehaviors`(:1299-1322) 在 State≥InvalidVertices1 时触发(:382-389)：`OnChunkInitialized` 全局广播 + 逐格 `OnBlockGenerated`(contents≠0 才调)。

### 四趟内容(TCG24, 噪声→地表材料→装饰)

| 趟 | 步骤(GenerateOrder 升序) | 锚点 |
|---|---|---|
| pass1/2(各半区 z∈[0,8)/[8,16)) | 1000 `GenerateSurfaceParameters`(温度/湿度入 Shafts)、2000 `GenerateTerrain`(3D 密度场) | :325-329 |
| pass3 | 100 `GenerateCaves`、200 `GeneratePockets`、300 `GenerateMinerals`、400 `GenerateSurface`、500 `PropagateFluidsDownwards` | :331-335 |
| pass4(15 步) | 100 草与植物、200 倒木、300 树、400 仙人掌、500 南瓜、600 海带、700 海草、800 底吸、900 陷阱、1000 常春藤、1100 坟墓、1200 石冢、1300 雪与冰、1400 基岩与空气、1500 流体顶面 | :337-351 |

- `ChunkGenerationStep` 字段：ShouldGenerate/GenerateOrder(默认 1600，越小越早)/Name/ErrorLogged(ChunkGenerationStep.cs:4-20)；异常被 `CallChunkGenerationStepAction`(TCG24:2423) 吞且**每步骤对象只报一次**。
- **地形塑形**：`CalculateHeight` 7 项合成(海退/海岸岛/丘陵/山地/河流/细噪/偏置)，山地因子取 ridged 噪声；河流只降不抬(`Min` :476)；密度场 4×8×4 格点插值行进(建场 :596-623、走场 :658-687，材料按"距地表深度"分层 :669)；湍流按深度门控。`CalculateHeight` **不含湍流**，与实画地表不一致——洞穴就踩了这坑(TCG24:941-943)。
- **群系体系**：无 Biome 类。每列温度/湿度=2D 噪声写入 Shafts(pass1)；`GenerateSurface`(TCG24:701-726) 自上而下找首个不透明格按温度/湿度/高度改写地表材料；植被步骤按气候+森林密度分布。
- **矿脉**：静态笔刷池(固定种子)；`GenerateMinerals` 对 3×3 邻域每区块算一遍，`Random(m_seed + i + 119*j)`(只由邻区坐标派生保证接缝对齐)+burn-in；数量=基数+山地因子×噪声，y 区间/宿主硬编码；`PaintFastSelective`(TerrainBrush.cs:214-236) **出界即丢、整值相等才画**(宿主须 data/light=0)。
- **存档**：卸载时 SaveChunk(:480)、退出时 `SubsystemTerrain.Save`(:587-605) 全量落盘。

### 区块持久化链 TerrainSerializer

```
SubsystemTerrain.Initialize :523  TerrainSerializer = new TerrainSerializer23(dirName)  // 2.4 唯一后端
运行时：TerrainUpdater 卸载 :480 SaveChunk(chunk)
退出：SubsystemTerrain.Save :587-605  等 UpdateEvent → 遍历 AllocatedChunks 全部 SaveChunk
老格式：TerrainSerializer14/129/22 仅被 VersionConverter10To14/21To22/22To23 读写
  (VersionConverter22To23.cs:75-76 用 TS22 读→TS23 写完成升级)
```

- **存档门槛**：`SaveChunk` 仅在 `State > InvalidContents4 && ModificationCounter > 0` 时落盘(TerrainSerializer23.cs:593-599；22:58-64 同)——半生成区块不存。
- **RegionFileStorage(默认，TerrainSerializer23.cs:278-564)**：每 16×16 区块一个文件 `Regions{suffix}/Region X,Y.dat`(:445)；头=FourCC "RGN1"(:305)+256 目录项×8 字节(offset,size)(:294-296)；数据区自 2052 起(:300)，每条目前置 4 字节 "CHK1"(:307/:518)；条目间留 1024 字节余量(:287/:561)，放不下就整文件经 tmp 重建再换名(:382-442)；单 Region 上限 256MB(:541)、句柄 LRU 100(:285/:473-475)。
- **SingleFileStorage(备用)**：单文件 `Chunks32fs.dat`(:25)；文件头 786444 字节=魔数 0xDEADBEEF(:27)+NodeSize(:31)+空闲链头(:8)+65536 个 12 字节区块描述符(:35-37)；节点 1024 字节成链表，节点头打包"下一节点偏移或末段长度"(:236-252)；加载沿链拼接(:102-112)。
- **压缩(TerrainSerializer23.cs:652-724)**：先 256 字节 Shafts(每列 `温度<<4|湿度` 挤进一字节 :656-659)；再按 y→x→z 序对整格 value(光清零 :665)做 RLE——游程长度藏进 light 位(≤15：4 字节 `count-1`；≤271：5 字节 :750-764)；最后 Deflate Fastest(:688/:766-773)。解压若未精确填满 16×256×16 则抛"Corrupt chunk data"(:719-723)。
- **老格式对比**：TS22 `Chunks32h.dat` 定长槽 263184 字节(4 格 value=4B + 256 shaft=1KB)，TOC 65537 项(:21/:40/:49)；TS129 `Chunks32.dat` 同构但 ChunkSizeY=128(:13)；TS14 `Chunks.dat` 格子仅 2 字节(:98-100)。
- **笔刷补画**：TCG23/24 画树时 `chunk.AddBrushPaint` 记录(TCG23:1274、TCG24:1230)，`TerrainChunk.AddBrushPaint/ApplyBrushPaints`(:239/:243)——但全项目无调用方，当前是**闲置 API**。

## 坑与对策

- **步骤异常全静默**：ErrorLogged 挂在步骤对象上只报一次(TCG24:2423-2436)，之后所有区块所有异常无声。对策：委托内自包 try/catch+计数日志，给步骤起 Name。
- **四趟内跨区块读写**：邻居可能还没生成。对策：只用 `chunk.Get/SetCellValueFast`，跨区结构学原版"3×3 邻域各自画自己那片+种子只由 (i,j) 派生"。
- **挂到钩子里的步骤才会被排序**：`TerrainContentsGenerator24Initialize`(:352-358) 在 Sort 前；之后(如 OnProjectLoaded)Add 不排序。对策：自己 `Sort((a,b)=>a.GenerateOrder.CompareTo(b.GenerateOrder))`。
- **老存档/平面世界钩子不触发**：生成器选型看 `OriginalSerializationVersion`(SubsystemTerrain.cs:551-584)。测试地形模组要新建 2.4 常规世界。
- **`TGWater=false` 是死字段**：只声明无读取点，海洋照生成。
- **SeaLevelOffset 漂移矿脉**：`OceanLevel=64+offset`(:252) 而矿 y 区间硬编码，改海平面会改变矿相对深度。
- **清空原版笔刷池**：矿笔刷按整值比较宿主(PaintFastSelective :214-236)，`Int(0,-1)` 返回 0 → `m_coalBrushes[0]` 越界，异常被吞全进程只报一次。对策：清空同时补自己的笔刷。
- **OnTerrainContentsGenerated 在子线程**(:345/:548)：别碰 GL/UI/FindSubsystem；只操作 chunk 的 Fast 接口。
- **矿刷宿主是"整值"不是 contents**：煤宿主=Granite(3)、铁/硫磺/钻石/锗=Basalt(67)、硝石=Sandstone(4)——带 data/light 的格子永远画不上；想兼容染色/元数据格要自己写 Painter。
- **跨版本笔刷种子不同**：21/22/23=Random(17)，24=Random(24)(上表末行)——同一世界种子在 2.3 与 2.4 生成器下矿物形状不同，别用 2.3 存档验 2.4 矿表。
