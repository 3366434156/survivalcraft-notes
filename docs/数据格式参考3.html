数据格式参考 3 · 界面XML/语言包/动画JSON

域: SC引擎 · 更新: 2026-11-01 · 状态: 解析器全读+低频控件逐类核实（样例 XML 2 个全读 + Lang/动画样例关键段实读；元素/属性名来自 Screens+Dialogs+Widgets+Styles 全目录统计；低频 26 种控件逐类实读源码；平台名全集与 Lang 数组合并行为实读核实）

一句话定位

自定义界面 Widget XML、语言包 Lang JSON、动画配置两级 JSON 的 schema 与装载链，AI 写这三类 mod 数据文件前先查本页。

怎么用（AI 视角）

  1. 写界面/语言包/动画配置前：在对应节找到 schema 表 → 抄"最小样例"（注明原版出处）；属性/键名一字不差，大小写敏感。
  2. 方块表/配方/衣物/实体格式见 数据格式参考·数据格式参考2；Widget 类层次见 09-UI与Widget体系、17-Screen屏幕族、18-Dialog对话框族。

  • 屏级样例：Survivalcraft\Content\Assets\Screens\SettingsAudioScreen.xml:1-32（TopBar 复用 + 滑条）。

模组如何覆盖/提供 XML

  • mod 包（.scmod zip）内 Assets/ 下文件按去掉前缀的路径注册进内容表：ModEntity.CombineContent（Survivalcraft\ModsManager\ModEntity.cs:279-298）→ ContentManager.Add 按 AbsolutePath AddOrUpdate（Survivalcraft\Managers\ContentManager.cs:133-135）→ 同路径后注册者覆盖先注册者（原版内容先装载，mod 后装载）。
  • 覆盖原版界面 = mod 包内放 Assets/Screens/同名.xml（Dialogs/Widgets/Styles 同理）；覆盖文件必须保留原文件里代码按 Name Find 的控件名，否则屏 ctor 处 NullReference。
  • 新增界面 = 新 XML + 代码里自定义 Widget 子类按上述两行装载（照抄 SettingsAudioScreen.cs:11-12）。

坑

  • 属性写错=静默失败：未知属性只 Warning；只有未知元素才抛异常。自查法：对照本页属性表与目标控件类源码。
  • [类:键] 只有 LabelWidget.Text 解析（Survivalcraft\Widget\LabelWidget.cs:14-23，→ LanguageControl.GetContentWidgets）；FontTextWidget.Text 及代码里动态赋文本不翻译。
  • Style 即二次装载：{...} 取回 XML 片段再 LoadContents 一遍，与节点自身属性合并时后装载者生效；别指望 Style 里能带事件。
  • XML 无法绑事件：按钮回调必须代码 Find；Name 全树不必唯一但同屏内同名会互相干扰 Find。
  • 平台差异：_IncludePlatforms/_ExcludePlatforms（空格分隔）与 VersionsManager.PlatformString 全串精确比对、大小写敏感；平台名全集 6 个：Windows / Android / Linux / Browser / IOS（大写 IOS，非 iOS）/ Other（编译目标兜底；来源 VersionsManager.cs:11-15, 17-33，无 VR 平台名）。写错平台名=节点整块消失且不报错（Widget.cs:721-740）；两属性都写时恒包含（Exclude 被忽略）。排查"控件不见了"先查下划线属性。

节2 · Lang 语言文件

文件与装载

  • 原版 8 个：Survivalcraft\Content\Assets\Lang\{culture}.json（en-US/zh-CN/ru-RU/es-419/pt-BR/ro-RO/tr-TR/vi-VN）。JSON 而非 key=value 行。
  • 模组接入点：ModEntity.LoadLauguage（Survivalcraft\ModsManager\ModEntity.cs:167-186）——mod 包内 Assets/Lang/en-US.json 总是装载（LoadEnglishJson），Assets/Lang/{当前语言}.json 仅非 en-US 时装载；按 mod 列表逐个调用（Survivalcraft\ModsManager\LanguageControl.cs:380-383）。
  • 合并协议 MergeJsonNode（LanguageControl.cs:180-238，逐行核实）：对象=按键递归深合并、新键 DeepClone 后加入（194-199）；数组=按索引逐元素合并、新数组更长则尾部追加（211-218）、更短则不截断原数组尾部（220-223）；两侧类型不一致或为标量=整节点替换（202-204, 225-235）。
  • 切语言 ChangeLanguage（LanguageControl.cs:371-406）：重载所有 mod 语言包 → SetUsual 缓存常用词 → 整表重建屏（GameScreen 除外）。

结构样例（原版 zh-CN.json 实读，节选自文件头 30 行 + 3506-3509 行）

json
{
  "Language": { "Name": "简体中文" },
  "FurnitureBlock": [ "将家具组合成交互式家具设计", "家具设计种类过多" ],
  "ContentManager": { "1": "资源 \"{0}\" 的类型为 {1}，但请求的类型是 {2}" },
  "ContentWidgets": {
    "SettingsAudioScreen": { "1": "调整音频设置", "2": "音效音量：", "3": "音乐音量：" }
  }
}

顶层节=类名；值可命名字符串键、数字字符串键（"1"）或 JSON 数组（按索引取，Get 双兼容，LanguageControl.cs:293-311）。

坑

  • mod 必带 en-US.json：只写 zh-CN 时英文环境回退原版 en-US（无此键）→ 界面直接显示键名字符串。
  • 数组按索引合并：MergeJsonNode 逐索引覆盖（LanguageControl.cs:211-223）——在原版数组中间插值后，mod 数组插入点之后的每个值都会覆盖前移一格的原版索引，译文整体错位；扩展原版数组必须保持前缀对齐、只在尾部追加。反过来短数组不截断原版尾部，可以只覆盖前几项。
  • 键大小写敏感：JSON 下钻是精确匹配；"Usual" 节键还有小写习惯（"ok"/"not allowed"），照抄原版。
  • 屏文本键挂在 ContentWidgets 节：XML 里 [我的屏:1] 对应 ContentWidgets.我的屏.1，不是顶层 我的屏。
  • 数字键是字符串："1" 而非 1；数组与字符串键可混用但语义不同（数组追加不改已有索引）。

animations.{别名}状态规则里引用的动画：{source: "driver:名" 或 clip 名, speed, loop, startPhase, endPhase, blendDuration, preservePose, driverArgs, events, onComplete, onInterrupt, rootMotion}（AnimationConfig.cs:28-113）
parameters.{名}驱动器/条件可用的参数初值（bool/int/float/Vector3）
rootBoneRotation(度) / rootBoneTranslation / modelScale / boneAliases根骨骼与缩放、骨骼别名
  • driver.type：用 AnimationDriverManager 注册名，内置驱动器全部双名注册（HumanWalk 与 HumanWalkDriver 等价；Survivalcraft\Animation\AnimationDriverRegistration.cs:28-73）；查表未中再回退反射（AnimationConfigLoader.cs:469-475）。driver.properties 按名反射写入驱动器属性（AnimationConfigLoader.cs:520+）。
  • animation.source 协议前缀 animation://（AnimationConfigLoader.cs:16）；"driver:HumanWalk"=直接用层驱动器输出（Human.json:55）。

最小样例：Survivalcraft\Content\Assets\Animations\Human.json:1-166 全文——template 引用 + 4 层驱动器 + 4 组状态规则（condition: "true" 兜底放末尾，82-84 行 animation: null 空态）+ 40 余参数。

坑

  • 引用模板后 index/blendMode 无效：层序与混合模式只能改模板文件（AnimationConfig.cs:140-151）；想免改原版模板就省略 template 走内联 layers。
  • 模板名写错静默降级：未知模板名回退 Simple（单 Base/Override 层），不报错（AnimationConfigLoader.cs:344-347）——驱动器全不生效时先查 template 名。
  • weight ≤0 = 1：想"权重 0 关层"做不到，用 states 规则回 null 空态。
  • states 规则顺序敏感：首个命中生效，true 兜底必须在末尾（Human.json:53-57, 82-84 的写法）。
  • 新驱动器要注册双名：仿 AnimationDriverRegistration 同时注册 X 与 XDriver，配置里两种写法才都可用（A26 结论，本日复核 28-33 行）。
