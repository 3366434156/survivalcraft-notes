SC 引擎媒体装载、动画与 VR

域: SC引擎 · 更新: 2026-10-31 · 状态: 全读(140/140；Survivalcraft\Animation 29 文件 A26 补全；OpenXrVrBackend.cs 1690 行 A22 补深读，VR 全链实读)

一句话定位

Engine.Media（图片/音频/模型/字体装载解码）、Engine.Animation（层混动画状态机/根运动/IK）、VR（OpenXR 后端全链：实例→会话→动作→交换链→提交）三域怎么组织。

核心机制

1. 媒体装载统一模式：嗅探→PeekStream→Load/Stream 双轨

  • 所有媒体入口先验魔数再选解码器：图片 Image.DetectFormat（Image.cs:127-130，9 格式注册于 Image.cs:17-27）；音频按 Flac("fLaC")→Wav("RIFF/WAVE")→Ogg("OggS")→Mp3(ID3v2) 顺序（SoundData.cs:39-48）；模型 glb("glTF")→gltf('{')→Collada(XML)（ModelData.cs:64-85）。
  • 无参 Load(Stream) 用 PeekStream 预读头部再透传，不消耗流：音频预读 64 字节（SoundData.cs:94-98）、模型预读 256 字节（ModelData.cs:114-118）。PeekStream.Read 先服务缓冲再透传（PeekStream.cs:58-81）。
  • 每格式一对静态方法：Load→SoundData（全量 16bit PCM）、Stream→StreamingSource（分块解码）。四种 StreamingSource 构造时都把整份文件拷进 MemoryStream（Wav.cs:42-48、Mp3.cs:36-41、Ogg.cs:23-29、Flac.cs:184-188），"流式"实为内存中分块解码，非磁盘流。Duplicate() 再拷一份供多声道复用。
  • 字体双轨：位图 BitmapFont.Initialize(png流, lst流) 读 .lst 元数据（BitmapFont.cs:101-192），或 InternalLoad 从整图自动切格——洋红 (255,0,255) 为分隔/透明键（BitmapFont.cs:528-547、424-438），并按左右深度图自动算 kerning（BitmapFont.cs:451-491）。矢量 VectorFont 每样式一条 FontSystem 链，缺字形 run 切分回退位图字体（VectorFont.cs:284-360）。
  • 引擎无视频播放器：全库无 VideoPlayer/MediaManager 类，"video" 仅 Storage/Window 无关命中。

2. glTF 装载管线与材质扩展

链路：GltfLoader.Load → SharpGLTF ReadContext(ValidationMode.Skip，外部 .bin/纹理走 LoadExternalStreamCallback 回调) → ConvertToModelData 五步（GltfLoader.cs:73-103）：①GltfMaterialConverter（先分析纹理 sRGB/Linear：BaseColor/Emissive=sRGB，Normal/MetallicRoughness/Occlusion=Linear，GltfMaterialConverter.cs:55-71；纹理延迟加载存 SourceImage）②GltfBoneConverter（多根节点自动建虚拟 "Root"；按深度拓扑排序保证父在前，GltfBoneConverter.cs:23-94）③GltfMeshConverter（每个 primitive 一个 ModelMeshData 防同 mesh 异材质误合绘，GltfMeshConverter.cs:46-74；缺 TANGENT 时 unweld 后用 Lengyel 公式生成，w 方向与标准相反，GltfMeshConverter.cs:519-594；glTF CCW 索引翻转为 0,2,1，GltfMeshConverter.cs:386-397；索引恒 32 位）④ConvertSkins（只取第一个 Skin，IBM 缺失补 Identity，GltfBoneConverter.cs:113-156）⑤GltfAnimationConverter（骨骼通道均匀重采样为线性关键帧：时长×30fps、上限 300 帧，CubicSpline 在此被拍平，GltfAnimationConverter.cs:627-631；KHR_animation_pointer 生成 Action<float> 闭包直改材质属性并 mat.Version++ 供渲染器重建 UBO，GltfAnimationConverter.cs:152-217；KHR_node_visibility 以 0.5 阈值切 Meshes/Lights IsVisible）。

  • 材质扩展架构：MaterialExtensionManager.AvailableExtensions 21 个开关（MaterialExtensionManager.cs:8-30）→ MaterialExtensionRegistry 工厂创建（MaterialExtensionRegistry.cs:6-21）→ 各扩展 LoadFromGltf 取值、AppendDefines 经 IShaderDefineBuilder 出着色器 define（如 MATERIAL_CLEARCOAT）。SharpGLTF 不认的扩展（volume_scatter）走反射读 UnknownNode（MaterialExtension.cs:98-145）。
  • 骨骼动画采样：AnimationPlayer 按骨骼合并通道，缺分量回退 rest pose 分量（AnimationPlayer.cs:571-591）；相位范围 [startPhase,endPhase] 支持反向播放，循环 wrap 时用 m_wrapOvershoot/m_keyInterval 做边界插值防跳变（AnimationPlayer.cs:303-342、640-671）；速度 0 直接钉在 StartPhase（AnimationPlayer.cs:280-283）。

3. 动画分层栈与状态机

帧流程 AnimationController.Update（AnimationController.cs:257-283）：同步引擎参数 → 参数脏检查通过才重评状态规则（AnimationParameters m_isDirty，AnimationParameters.cs:14-29）→ 更新动态属性（每帧评 NCalc 表达式设 Speed/Loop，AnimationController.cs:647-676）→ 各层 Update → 推进根骨骼变换混合 → 应用根运动（仅 Index=0 的 Base 层）→ 检查 OnComplete。

  • 层（AnimationLayer）：Override 权重渐入/渐降（m_activating/m_deactivating，AnimationLayer.cs:534-579）、Additive 淡出到 Identity 的过渡、骨骼遮罩=include 子树−exclude 子树并按引用失效缓存（AnimationLayer.cs:159-195）、过渡完成时把 TargetPlayer 晋升为主播放器并迁移事件订阅（AnimationLayer.cs:592-603）。
  • 状态规则：嵌套 rules 决策树，外层失败短路整组（AnimationController.cs:880-903）；切换检测=匹配路径+解析后 source 双重比较，source 支持 "[参数名]" 动态换动画（AnimationController.cs:806-828、951-960）；animation:null/source:null → 停用层（driver 层用 Deactivate、片段层用 DeactivateAndClear，AnimationController.cs:834-870）；空 source 的 ApplyAnimationToLayer early-return 维持现状（AnimationController.cs:979-981）。别名合并 MergeWithAlias：caller 显式字段（HasXxx）覆盖 alias 默认（AnimationController.cs:912-929）。
  • 混合（AnimationBlender.BlendLayers）：逐层采样到预分配缓冲，Override 按权重 TRS 分解插值，Additive 为 existing * Lerp(I, incoming, weight)（AnimationBlender.cs:81-91）；底层 Weight<1 时与 rest pose 插值使权重渐降有效（AnimationBlender.cs:55-65）。矩阵混合统一=Scale(Lerp)×Rotation(Slerp)×Translation(Lerp)。
  • 最终输出 ComputeBoneTransforms（AnimationController.cs:1259-1279）：层混合 → 活动层采 KHR_animation_pointer（材质/UV 变换动画）→ 采 morph 权重写入 ModelMeshPart.MorphWeights → IK 后处理。
  • 混合空间 BlendSpaceSource：1D 相邻两点插值、2D 取最近 4 点反距离权重（BlendSpaceSource.cs:519-585）；SyncTime 模式统一推进归一化时间（BlendSpaceSource.cs:251-265）；成员动画强制 Loop=true（BlendSpaceSource.cs:165）。

4. 根运动与 IK

  • 剥根：启用 root motion（非 None/AddImpulse）时，RootMotionStrip.StripRootTranslation 把 SourceBone→根 链上每骨 translation 还原为 rest（RootMotionStrip.cs:12-32），在层采样点按 RootStripInfo 执行（AnimationLayer.cs:633-634、661-662）。
  • 提取：RootMotionCache 按动画名缓存根骨骼 translation 采样表，GetVelocity 处理循环回绕（RootMotionCache.cs:88-111）；速度经父链旋转（ComputeParentChainRotation，AnimationController.cs:506-519）→×ModelScale→×EffectiveRootRotation 变换到实体空间（AnimationController.cs:430-436）。
  • 应用：TranslationApplier 三模式——Blend（SmoothDamp/WeightedAverage/SpringDamper 三融合法）、AddImpulse（在 ImpulsePhase 相位跨越时按 Average/Peak/Weighted 法算冲量，AnimationController.cs:382-428）、Override 直接覆盖；VelocityMask 按轴放行、MaxSpeed/MaxImpulse 钳制（TranslationApplier.cs:26-97）。Scale 走 CollisionBoxApplier 指数衰减过渡碰撞盒（CollisionBoxApplier.cs:35-68）。每动画根骨骼旋转/平移覆盖可与顶层配置 smoothstep 混合（AnimationController.cs:563-608）。
  • IK：链=末端骨向上收集至 maxChainLength，延迟构建（IKSolver.cs:95-115）；算法按链长自动选：2→SingleBoneIK、3→TwoBoneIK（余弦定理+Hint 弯曲方向）、>3→CCD（单次限幅 45°）（IKSolver.cs:328-335、CCD.cs:76-79），FABRIK 仅显式指定时用。目标 SmoothDamp 平滑（IKSolver.cs:370-432）；Aim-only 目标自动生成 bindRoot+aimDir×链长 位置（IKSolver.cs:235-258）；不可达三策略 ExtendToward/KeepPose/UseLastValid（IKSolver.cs:466-487）；关节限位=欧拉分解→Clamp→按 RotationOrder 重建（JointLimit.cs:36-47）。所有算法用 IKUtils.ApplyModelRotation 施加模型空间旋转增量保持关节世界位置（IKUtils.cs:48-69）。驱动器对蒙皮模型 Override 语义自动补回 rest 枢轴平移（AnimationDriverManager.SampleWithPivot，AnimationDriverManager.cs:126-151）。

5. OpenXR 后端全链（OpenXrVrBackend.cs，1690 行）

装配与平台拆分：Program.Initialize 装后端（Survivalcraft\Game\Program.cs:266-270）——Windows/Android 各 new 一个平台子类 SetBackend 给 VrManager 静态代理。抽象基类只留 3 个平台钩子：GraphicsBindingType/GetGraphicsBindingSize/PopulateGraphicsBinding（OpenXrVrBackend.cs:89-91）；Windows 填 wgl DC/GLRC（WindowsOpenXrVrBackend.cs:11-20），Android 填 EGL display/context/config（AndroidOpenXrVrBackend.cs:11-29）。主循环接线：Program.Run 开头 vrFrame=IsVrStarted&&BeginFrame()（Program.cs:282），finally 里 EndFrame()+Update()（:359-362）。

实例链 DoInitialize（:184-349，全软降级）：Android 先 xrInitializeLoaderKHR（JVM+Activity 指针，:187-210，必须先于一切 OpenXR 调用否则扩展不可见）→ 查 XR_KHR_opengl(es)_enable（缺则放弃 :219-222）+ 可选 XR_EXT_local_floor/XR_KHR_android_create_instance/XR_BD_controller_interaction（:224-231）→ xrCreateInstance（AppInfo "Survivalcraft"、API 1.0，:233-281）→ xrGetSystem(HMD)（:283-294）→ GetOpenGLGraphicsRequirements（:296-329）→ EnumerateViewConfigurationView 取推荐眼缓冲尺寸（:331-345）→ IsAvailable=true（:348）。任何一步失败只 Log+IsAvailable=false，不抛异常。

  • 双轨初始化：Windows 下 Initialize 丢后台 Task.Run（xrCreateInstance 在"有 runtime 无 HMD"时同步拉 runtime broker 卡数秒，:150-172，幂等）；StartVr 先 m_initTask.Wait() 收口（:356-359）。Android 同步（:174-181）。失败资源清理 StartVr catch 里做（:373-378）。

会话链 StartVr（:351-379）→ DoStartVr（:381-426）：xrCreateSession（平台 binding 结构体 stackalloc+memset+手写 StructureType，:428-445）→ Android 设 RendererMain 线程（:387-397）→ CreatePlaySpace → 重置 recenter 状态（:402-406）→ SelectSwapchainFormat → 双眼 CreateSwapchain+FBO（:410-412）→ 视图数组 → CreateActions。启动触发点：LoadingScreen 装载步（LoadingScreen.cs:190-204，Android 头显强制 UseVr :186-189）与设置页开关（SettingsGraphicsScreen.cs:43-51）。

会话状态机：PollEvents 泵 EventDataSessionStateChanged → HandleSessionStateChange（:1484-1498）：Ready→xrBeginSession（成功隐式记 Synchronized，:1500-1511）；Stopping→xrEndSession（:1513-1515）；LossPending/Exiting→IsStarted=false。BeginFrame 门（:1032-1041）：LossPending/Exiting 翻 IsStarted；非 Focused/Synchronized/Visible（Idle/Ready）只轮询不调帧函数。

参考空间三级回退 CreatePlaySpace（:1517-1553）：LOCAL_FLOOR（OpenXR 1.1；规格上 recenter 不动 Y，Quest/SteamVR 违规）→ Stage → Local（眼级兜底）。每次 ReferenceSpaceChangePending 事件销毁重建（:1471-1480）。

Recenter Y 补偿（事件快照+次帧差分）：PollEvents 收 ReferenceSpaceChangePending 且 tracking 已建立 → 记 m_hmdYBeforeRecenterRaw 快照 + m_recenterPending（:1471-1480，m_trackingEstablished 首个有效 HMD 姿态置位 :1234-1237，防启动期假事件）；下一帧 UpdateHmdState 算 delta=快照−当前 rawY，>1cm 才累积进 m_recenterYOffset（:1239-1251）；补偿贯穿四路：HmdMatrix.Translation（:1253-1257）、GetEyeFrame 的 viewMatrix(−offset)/CameraPosition(+offset)（:1110-1120）、控制器矩阵（:1292-1296）、EndFrame 提交 pose（:1139-1149）。

交换链：SelectSwapchainFormat（:447-474）优先 Srgb8Alpha8→Rgba8→首个（游戏输出 sRGB 值且 FRAMEBUFFER_SRGB 关闭，声明 sRGB 告 compositor 已伽马，防 Meta 二次伽马发灰 :463-465）。CreateSwapchain 每眼一条（ColorAttachment|Sampled、单 sample :491-552）+ CreateFBO 每眼一条（DepthComponent24 renderbuffer+image[0]，:554-575）。GetEyeFrame 每次 Acquire+Wait（timeout 1s）后把新图像 FramebufferTexture2D 重挂该 FBO（:1100-1104）——FBO 句柄恒定、颜色附件每帧变。

动作系统 CreateActions（:577-650）：单 actionSet "gameplay"；每手 13 动作：trigger/grip/grip_click/menu/stick_x/stick_y（拆 X/Y 因无 Vector2f API :602）/pose/stick_click/primary|secondary（左 X,Y=右 A,B）/thumbrest/trackpad_x/trackpad_y。SuggestBindings 9 个 interaction_profile（Quest Touch/WMR Motion/Vive/Index/Touch Pro/Touch Plus/PICO Neo3/PICO 4/Vive Focus3，:688-945；WMR squeeze 是 click、Vive trackpad 兼 stick 与 trackpad、PICO 4 Menu 仅左手）。建议绑定一票否决：任一 StringToPath 失败弃整 profile（:951-964）；ErrorPathUnsupported 仅 Verbose（runtime 不支持属正常 :979）。AttachSessionActionSets（:623-631）→ pose 动作建 ActionSpace（identity :637-649）。

控制器类型探测 DetectControllerType（:985-1023）：GetCurrentInteractionProfile→PathToString 映射 9 profile→5 枚举（:1005-1016，vive_focus3 归 MetaQuestTouch）。必须首次 SyncActions 后（此前返回 NULL_PATH :633-635），BeginFrame 里 Unknown 且 <30 帧逐帧重试（:1074-1080）。

帧循环：BeginFrame（:1027-1086）=PollEvents → 状态门 → xrWaitFrame（节拍阻塞 :1043-1046）→ xrBeginFrame（:1048-1049）→ ShouldRender==0 仍返回 true（EndFrame 自动走空层 :1051-1053）→ xrLocateView（PrimaryStereo/playSpace/PredictedDisplayTime :1055-1065）→ UpdateHmdState → SyncActions → 探测 → UpdateControllers。GetEyeFrame（:1088-1128）返回 Fbo/ViewMatrix=Invert(Pose)/非对称投影/CameraPosition；ReleaseEye（:1130-1133）；EndFrame（:1135-1185）组 CompositionLayerProjection 提交（BlendMode.Opaque，fixed 块防 GC 移数组 :1168-1180）；EndFrameEmpty（:1187-1197，LayerCount=0 防残影）。

HMD/控制器状态：UpdateHmdState（:1201-1258）HMD 位置=双眼中点、朝向=左眼四元数，HeadMove=XY 平移差（:1228-1232）。UpdateControllers（:1275-1338）连接判定=LocateSpace 的 Position+Orientation valid 位（:1284-1286）；Grip=float≥0.5 或 bool click 双路（:1303-1306）。IsButtonDown 映射（:1385-1404）：Trigger≥0.5、Trackpad→StickClick、TrackpadCenter=StickClick 且 |x|,|y|<0.3、四方向=真 trackpad 轴 ±0.5；IsButtonDownOnce 带 0.5/0.4 滞回（:1406-1425）。死区是重映射式 ApplyDeadZone（剪死区并重缩放满量程，:140-148）。

眼变换与投影：GetEyeToHeadTransform 只含 IPD 平移（双眼相对中点偏移经 HMD 逆旋到头部局部，:1429-1447），旋转由相机 LookAt×HMD 承担防双旋转；CreateProjectionMatrix 四 tan 非对称投影+GL clipZ[−1,1]（:1570-1592）。WalkingVelocity 恒零（OpenXR 不跟踪 :1596）、VrRenderTarget 恒 null（:127）。

销毁：StopVr（:1600-1616）swapchain/FBO→spaces/actions/session→instance 全序销毁，IsAvailable 保持 true 可重启（:1615）；Dispose 先等后台 init 防竞态（:1636-1644），挂 Window.Closed（VrManager.cs:62-65）。

坑与对策

  • MP3 检测名不副实：Mp3.IsFlacStream 实际检测 ID3v2 标签（Mp3.cs:83-90），裸 MP3（无 ID3v2）会被 SoundData.DetermineFileFormat 拒绝 → 给文件带 ID3v2 头，或用带扩展名的 Load 重载。
  • 带 ID3v2 的 FLAC 误判：Flac.IsFlacStream 只看首 4 字节 "fLaC"（Flac.cs:221-232），ID3v2 在前的 FLAC 落进 Mp3 分支解码失败 [推测] → 转存去掉 ID3v2。
  • WAV StreamingSource 定位错位：Position setter 用 SizeOf<WavHeader>(12)+偏移 而非 dataStart（Wav.cs:34），标准 44 字节头的文件 seek 偏早 32 字节 → 避免对 Wav StreamingSource 赋 Position，用 Load 后自行处理 [推测：仅 seek 路径受影响]。
  • "流式"音频双倍内存：四种 Stream() 都先全量拷进 MemoryStream → 长音乐勿走 StreamingSource，短音效用 Load。
  • WAV 装载限制：仅 PCM(1)/16bit/1-2 声道/8k-48kHz（Wav.cs:229-236）；SoundData 的 192kHz 上限对 Wav 不适用。
  • Image(LegacyImage) 转换器：Slice 长度误用 image.Height（Image.cs:84），宽 > 2×高 的图会抛异常 → 转换前确认尺寸或改走像素循环。
  • LegacyImage.GenerateMipmaps：尺寸收窄到奇数即 throw（LegacyImage.cs:66-69、150-152）→ 生成 mipmap 用 2 的幂尺寸。
  • CubicSpline 被拍平：glTF 动画装载时重采样 30fps、上限 300 帧（≈10 秒），更长动画后半段细节丢失 → 长动画接受线性精度或拆分。
  • 字体透明键：位图字体以洋红为切格/透明键，位图内含纯洋红像素会被吃掉 → 美术导出避开 (255,0,255)。
  • 矢量字体坏面：CFF2-only 可变字体（如 Android 16 NotoSansCJK）在 EngineSharpAstroSource 构造时抛 NotSupportedException（EngineSharpAstroLoader.cs:55-58）→ 匹配期用 FontLocator.Probe 拒收，建链侧已有整链降级兜底。
  • FABRIK 不自动选：IKSolver 默认算法表无 FABRIK（IKSolver.cs:328-335）→ 长链想要 FABRIK 须显式传算法名。
  • VR 发灰：swapchain 选 Rgba8 会让 Meta runtime 二次伽马 → 保持 sRGB 优先选择顺序（OpenXrVrBackend.cs:463-473）。
  • OpenXR 无 HMD 卡启动：xrCreateInstance 同步拉 runtime broker 数秒（Windows，:150-172）→ 引擎已后台 Task 化；但在 Initialize~StartVr 窗口期 IsVrAvailable=false 是"还没结果"不是"没有 VR"，别拿它门控启动（LoadingScreen.cs:191-194 注释明确此坑）。
  • BeginFrame true ≠ 有画面：ShouldRender==0 时仍返回 true，EndFrame 自动提交空层（:1051-1053、1182-1184）；自写循环若跳过 EndFrame 会破坏 xrWaitFrame 节拍（xrBeginFrame/EndFrame 必须成对）。
  • 眼 FBO 颜色附件每帧变：GetEyeFrame 每次 Acquire 后重挂 FramebufferTexture2D（:1100-1104）→ 别缓存"该 FBO 挂某纹理"的假设；眼内渲染必须发生在 GetEyeFrame 之后、ReleaseEye（RenderToEyes finally）之前。
  • ControllerType 启动后 30 帧内是 Unknown：探测需首次 SyncActions 后（:633-635、:1074-1080）→ VR 键位默认值要等 VrManager.BeginFrame 里类型已知才落盘（VrManager.cs:222-225）。
  • 绑定建议一票否决+静默：SuggestProfileBindings 任一路径 StringToPath 失败弃整 profile（:951-964），ErrorPathUnsupported 只 Log.Verbose（:979）→ 排查手柄没绑定要开 Verbose 日志。
  • recenter 补偿有 1cm 死区+tracking 门：启动期 ReferenceSpaceChangePending 不补偿（:1235-1237、1476-1479）；delta<1cm 忽略（:1246）。静置换物理高度再 recenter 会被拉回旧眼高，属设计行为。
  • VrRenderTarget 恒 null / WalkingVelocity 恒零：OpenXrVrBackend.cs:127/:1596 → 旧接口别用（VrManager 侧已标 Obsolete，VrManager.cs:43-44）。
  • StopVr 后可重启：StopVr 保留 IsAvailable=true（:1615），StartVr 可再走全链；只有 Dispose 才置 false 并等后台 init（:1636-1644）。
