家具系统（FurnitureBlock 227 · 设计表 · 组合合成 · 存档全链）

域: SC引擎+mod场景 · 更新: 2026-11-02 · 状态: 全链今日实读（FurnitureBlock / FurnitureDesign / SubsystemFurnitureBlockBehavior / ComponentFurnitureInventory / FurnitureInventoryPanel / FurniturePacksManager / BuildFurnitureDialog / 3 个家具电元件 + FurnitureSet·FurnitureGeometry·FurnitureInteractionMode·SubsystemHammerBlockBehavior 全文，行号均本日现行代码） · 关联: 04-方块系统 · 15-电学与机构 · 16-玩法物品与背包 · 11-存档持久化 · Mod开发配方2

一句话定位

自定义家具不是一种方块而是一套两级数据：FurnitureBlock（227）只是壳，data 里装 13bit 设计编号；真正的形状是 FurnitureDesign——一张 resolution³ 的体素格（每格填任意方块 value），由玩家拿锤子对搭建体"雕刻"生成、存在世界级设计表里，所有家具方块共享这 8192 个槽位。

1 data 位布局（FurnitureBlock = 227）

Terrain.MakeBlockValue(227, 0, data)，data 位域（读写函数全在 Survivalcraft/Block/FurnitureBlock.cs:604-627）：

位内容读写
0-1旋转 0-3（绕 Y，每 90°，对应 4 个预置矩阵 m_matrices :12-19）GetRotation/SetRotation :604-606
2-11设计编号低 10 位GetDesignIndex :608、SetDesignIndex :610-618
12-13阴影强度系数 0-3（几何不透明占比自动算出，FurnitureDesign.cs:594-614）GetShadowStrengthFactor :625
14发光位（IsLightEmitter 时写 1 → 恒发 15 级光 :266-271、无影 -99 :258-264）GetIsLightEmitter :627
15-17设计编号高 3 位同 :608/:610-618

设计编号合计 13bit = 8192，与 FurnitureDesign.maxDesign = 8192（FurnitureDesign.cs:25）咬合——这就是家具上限（并不存在"38 个设计位"的说法，38 是 Clothes.xml 的衣物条数，勿混）。

设计编号是间接引用：data 里只有索引，形状/碰撞/贴图全靠 SubsystemFurnitureBlockBehavior.GetDesign(index) 查世界级设计表（FurnitureBlock.cs 内 20 余处调用，如 :28/:250/:321）。表里查不到（index 越界/设计被 GC）→ 方块渲染为空但仍占格。

2 FurnitureDesign：一张体素格 + 派生缓存

Survivalcraft/Game/FurnitureDesign.cs（struct 风格类，1201 行）。没有模型路径/材质引用——家具几何完全由体素格运行时生成：

成员含义行号
m_resolution + m_values边长 2-256 的立方体格，每格一个完整方块 value（contents+data），0=空:23-27（Min/MaxResolution）、:49、SetValues :232-255
m_name≤20 字符（超长截断；首尾空格抛异常）:141-163
m_interactionModeNone/Multistate/ElectricButton/ElectricSwitch/ConnectedMultistateFurnitureInteractionMode.cs:3-7
m_linkedDesign多态链：同一家具的下一个状态，可成环:71、ListChain :514-526
m_furnitureSet所属家具集合（FurnitureSet 只有 Name/ImportedFrom 两个字段，FurnitureSet.cs:3-5）:37
m_terrainUseCount世界里引用此设计的方块计数（GC 依据）:43、增减在 SubsystemFurnitureBlockBehavior.cs:534-550

派生缓存（首次访问惰性计算）：

  • Geometry（CreateGeometry :616-852）：对 6 个方向逐层做"同 value 贪心合并大矩形"（FindLargestSize :1132-1148）生成 BlockMesh；贴图坐标 = 格子坐标除以 resolution 再落进成分方块自己的贴图槽（:767-775，槽位数取 GetTextureSlotCount :737 支持自定义图集）。成分方块带独立贴图时按纹理分组进 geometry.Draws（:739-760，FurnitureGeometry.cs:16）——同一设计可混用多种自定义贴图。mod 钩子 SetFurnitureDesignColor 在此改贴图槽/颜色（:729-735，ModLoader.cs:218）。
  • Box 包围盒（:89-96、CalculateBox :559-592）；MountingFacesMask/TransparentFacesMask 边界扫描（:1005-1068；"透明"=空格或玻璃 15，IsValueTransparent :1195-1200）；碰撞盒/交互盒递归细分 depth<2（CreateCollisionAndInteractionBoxes :854-933，交互盒额外合并、最小 0.0625）；火把点（格子内容为火把 31/纱灯 17 的格子聚成 ≤4 个光点 :935-980 → IsLightEmitter :107）。
  • MainValue 每列顶格众数（:982-1003）——家具的声音材质与破坏碎屑都借用成分方块（FurnitureBlock.cs:303-314、:342-355）。
  • Hash 用于设计查重（:77-87，Compare :454-470）。

3 全链：合成 → 摆放 → 换装 → 存档

3.1 合成（雕刻）：锤子 → 扫描 → 对话框 → 入表 → 掉落

  1. 锤子 OnUse 射线命中即调 SubsystemFurnitureBlockBehavior.ScanDesign（SubsystemHammerBlockBehavior.cs:10-16）。
  2. 六向洪泛收集连通的"可入家具"方块（ScanDesign :133-226）：IsValueAllowed → block.CanBlockBeBuiltIntoFurniture（SubsystemFurnitureBlockBehavior.cs:588-592；Block.cs:583，字段 CanBeBuiltIntoFurniture :31）。原版可建材：黏土/地毯/圆石/铜/砖/钻石/铁/孔雀石/大理石/玄武岩/岩浆/砂岩/沙/玻璃/石砖/水/纱灯/花岗岩/木板/火把（各 Block ctor）。水/岩浆顶层液体被排除（:594-603）。三轴最大 256（:174-179）。若起点本身是家具方块则走"复制"分支（:120-131）。
  3. 弹 BuildFurnitureDialog（:227）：命名（≤20 字符）、平移/镜像/旋转/改分辨率，三角形数超 MaxTriangles=65535 禁止制作（BuildFurnitureDialog.cs:76-92）。
  4. 确认后 TryAddDesign 入表（SubsystemFurnitureBlockBehavior.cs:60-81：先查重 Compare、再找空槽、不够先 GC、仍满→null 报错"家具设计种类过多"）。
  5. 掉落 clamp(resolution,4,8) 个家具物品（:243），mod 钩子 OnFurnitureDesigned 可改掉落数/是否拆原型/锤耐久（:247-259，ModLoader.cs:1312-1319）；非冒险模式销毁原型方块（:237、:274-286）。

3.2 组合合成（AdHoc，无配方表的程序化配方）

FurnitureBlock.GetAdHocCraftingRecipe（FurnitureBlock.cs:436-542，需无热量），由 CraftingRecipesManager 统一入口问询（16 页:82 同款范式，姊妹版见 ClothingBlock/CarpetBlock）：

配料产物行号
1 家具 + 1 按钮(142)克隆设计 → InteractionMode=ElectricButton 入表:469-490
2 家具 + 1 开关(141)两个克隆互设 LinkedDesign → ElectricSwitch:491-515
≥2 家具 + ≤1 电线(133)克隆链首尾互链 → Multistate（有电线则 ConnectedMultistate）:516-540

3.3 摆放与朝向

GetPlacementValue（:357-389）：点侧脸 → 旋转=被点面的对面；点顶/底面 → 按玩家视线定 4 向。不限放置表面——任意面均可放；MountingFacesMask 只影响电线绘制与电元件挂载面（:78、:575、FurnitureElectricElement.cs:10-27）。挖掉掉自身（旋转清零，:391-401）；可被活塞推（:629-632）。

3.4 "换装"两条路

  • 多态切换（状态机意义）：点击 Multistate/ConnectedMultistate 家具 → SwitchToNextState（SubsystemFurnitureBlockBehavior.cs:308-350）把 data 的设计编号换成 LinkedDesign.Index；ConnectedMultistate 还会六向泛洪联动 ≤4096 个相连家具（:313、:337-344）。
  • 染色（外观意义）：Paint（FurnitureBlock.cs:417-434）不是原设计改色，而是 CloneChain 逐节点染色后 TryAddDesignChain 注册成新设计再改写 data——染色件与原件并存。
  • 换装不换 data 的场合不存在：设计内容不可变，任何变化都产生新表项。

3.5 存档：世界级设计表 + 格子级引用 + 跨世界包

层存什么证据
世界 Project.xml（Subsystems→SubsystemFurnitureBlockBehavior）FurnitureDesigns 子袋：{索引: {Name,TerrainUseCount,Resolution,InteractionMode,LinkedDesign,Values(RLE)}}；FurnitureSets：{序号:{Name,ImportedFrom,Indices}}Load/Save :471-526；RLE 格式 数量*value, 串（FurnitureDesign.cs:419-452，解析 :201-228）。走 Project.Save 世界级落盘链（11 页:56），不在 chunk 里
chunk 格子只存 227+data（13bit 设计引用+旋转），设计本体集中管理OnBlockAdded/Removed/Modified 维护 terrainUseCount（:417-432、:534-550）
.scfpack（跨世界）zip 内单文件 FurnitureDesigns.xml（白名单校验）FurniturePacksManager.cs:64-78（Create）、:109-124（Load）；创造模式家具页导入/导出（FurnitureInventoryPanel.cs:284-406）

GC：Save 前、物品扫描后、打开创造家具页时都会跑 GarbageCollectDesigns（:352-354、:505、:552-586）：terrainUseCount==0 且全服物品扫不到、又不属于任何 FurnitureSet 的设计删表（链上成员随链保留）——FurnitureSet 兼"收藏夹/防 GC"双重身份。

4 交互与功能：家具能带什么功能

结论：家具的功能面 = InteractionMode 五态 + 电学三元件 + 发光/火焰粒子；没有坐、门、储物。

  • IsInteractive 只认 Multistate/ElectricButton/ElectricSwitch/ConnectedMultistate（FurnitureBlock.cs:287-301）；点击分流：Multistate 类走行为子系统换态（SubsystemFurnitureBlockBehavior.cs:456-469），电类走 CreateElectricElement（:544-560）——Button 点击/被投射物命中输出 10 电路步 1f 脉冲（ButtonFurnitureElectricElement.cs:23-43）；Switch 点击换态、电压=自身 Index≥Linked.Index ? 1:0（SwitchFurnitureElectricElement.cs:12）；Multistate 作为受电器，高输入驱动换态（MultistateFurnitureElectricElement.cs:11-24）。连接器方向：Multistate=Input、Button/Switch=Output（FurnitureBlock.cs:562-593）。
  • 发光家具：格子里埋火把/纱灯 → bit14 → 恒 15 级光 + 对应位置火焰粒子（SubsystemFurnitureBlockBehavior.cs:605-632）。
  • 无坐/开门/容器：全库无 Sitting 组件（grep 0 命中）；无柜门交互；ComponentFurnitureInventory 名字像"家具格子容器"，实际是创造模式家具目录的虚拟 IInventory（挂在创造背包实体上，槽位只读展示设计、AddSlotItems 空实现，ComponentFurnitureInventory.cs:6、:31-45、:99）——不是箱子。全库 IInventory 家具族仅此一个，25 页（方块实体与容器）未涉家具、与此一致。
  • 想给家具加新行为只能：① 上述电元件语义内组合；② mod 自己挂子系统扫描 227 方块做事（引擎未留 per-design 逻辑钩子，能 hook 的只有建色 SetFurnitureDesignColor、创建 OnFurnitureDesigned 两处）。

5 mod 视角：自定义家具清单

纯"数据"路线在这里不存在——设计不在任何内容资产 XML 里（Database.xml/BlocksData.txt 均无），只能运行时代码或玩家雕刻生成：

想做改哪要代码？
让某方块可被雕刻成家具ctor 设 CanBeBuiltIntoFurniture = true（照抄 CobblestoneBlock.cs:5）1 行
代码注入现成设计new FurnitureDesign(terrain) + SetValues(resolution, int[]) + SubsystemFurnitureBlockBehavior.TryAddDesign（SubsystemFurnitureBlockBehavior.cs:60-81；最短范例 FurnitureBlock.Paint :417-434 的 Clone→Add 链）要
换色/换贴图ModLoader SetFurnitureDesignColor（ModLoader.cs:218，触发点 FurnitureDesign.cs:729-735）覆写
控制雕刻产出OnFurnitureDesigned（ModLoader.cs:1312，触发点 SubsystemFurnitureBlockBehavior.cs:247-259）覆写
带电路功能玩家 AdHoc 合成，或代码注册时直接设 InteractionMode+LinkedDesign合成免代码
跨世界分发家具包引导玩家家具页导出 .scfpack（FurniturePacksManager 全链）免代码

最简照抄链：CobblestoneBlock.cs:5（可建材 1 行）→ SubsystemFurnitureBlockBehavior.ScanDesign（雕刻入口，勿动）→ TryAddDesign（入表）→ FurnitureBlock.GenerateTerrainVertices（渲染，勿动）。mod 全程最小干预 = 1 行字段 + 可选 2 个钩子。
