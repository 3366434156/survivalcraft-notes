链 1 · 挖方块：从按住到进背包

#发生什么出处
1玩家瞄准：相机射线 → TerrainRaycastResult（选中方块面）；输入映射见 10页01页 帧序
2ComponentMiner.Dig(raycastResult) 挖掘主函数（:192）：按住同一格累计 m_digProgress（工具时间 CalculateDigTime :212-215；等级不足归零提示 :216-230）ComponentMiner.cs:192-266
3⚡ OnMinerDig 钩子：可改 ref m_digProgress、可强制即时完成ComponentMiner.cs:234-241
4进度满 → GetDigValue → SubsystemTerrain.DestroyCell（:274-282）ComponentMiner.cs:267-282
5⚡ OnBlockDug 钩子：可改耐久消耗 durabilityReduction、静音 mute、统计增量ComponentMiner.cs:286-294（签名 ModLoader.cs:1260-1267）
6挖掘音效（声音材质表）+ 工具耐久扣减 + PlayerStats.BlocksDug 统计ComponentMiner.cs:296-301
7DestroyCell：GetDropValues 产掉落表 → 逐项过 OnItemHarvested 方块行为 → SubsystemPickables.AddPickable 生成掉落物（非实体）SubsystemTerrain.cs:429-459
8方块碎屑粒子：CreateDebrisParticleSystem → SubsystemParticles.AddParticleSystem（距视点 <16 格才生成）SubsystemTerrain.cs:461-467
9ChangeCell(0格) 走放置/破坏公共底座（链 2 第 3~6 步）SubsystemTerrain.cs:469
10掉落物物理：SubsystemPickables.Update → Pickable.Update（抛物/漂浮/消亡时长按分类 60~480s）SubsystemPickables.cs:178-203; Pickable.cs:153-196
11玩家拾取：ComponentPickableGathererPlayer.Update 距离判定 → 吸引（FlyToPosition :58）→ 收集范围内 CanGatherPickable（背包有空位或经验球，:14-32）→ GatherPickable：OnPickableGathered 行为 → ComponentInventoryBase.AcquireItems 入背包 → 归零移除+拾取音效ComponentPickableGatherer.cs:38-64; ComponentPickableGathererPlayer.cs:14-49
12⚡ 掉落物生成即发 OnPickableAdded（运行时与读档恢复都发）SubsystemPickables.cs:90-96, :233-239

深读：03页"生命/伤害结算链"、16页背包/掉落。

链 2 · 放置方块：从点击到光照重算

#发生什么出处
1ComponentMiner.Place(raycastResult)：可选 pending 模式（存按下时的目标，执行时用当时选中槽）→ DoPlace；成功扣背包 1 个ComponentMiner.cs:318-336
2GetPlacementValue 决定落点与新值；⚡ BeforeMinerPlace（可禁放）→ ⚡ OnMinerPlace（旧/新双签名，可代放 out Placed）ComponentMiner.cs:346-413
3占位/挤压检查（目标格非空、自身包围盒与方块碰撞盒相交禁止，创造/可跳放豁免）ComponentMiner.cs:417-442
4OnItemPlaced 方块行为 → DestroyCell(0,…,新值)（放置=以新值覆盖式破坏，同样走掉落/粒子）→ "Audio/BlockPlaced" 音效ComponentMiner.cs:444-465
5ChangeCell：⚡ TerrainChangeCell 钩子（out Skip=true 整段跳过原版写格） → 坐标合法 → 清光照位 → 快值相同直接返回 → SetCellValueFastSubsystemTerrain.cs:355-379
6区块 ModificationCounter++（存档判脏）→ 邻居区块状态降级到 InvalidLight（光照/网格在后续区块状态机里重算）SubsystemTerrain.cs:380-386
7记入 m_modifiedCells → ChangeCellToBehavior：旧行为 OnBlockRemoved → 新行为 OnBlockAdded（同值=OnBlockModified）；行为异常只记日志不崩SubsystemTerrain.cs:387-393, :396-427
8SubsystemTerrain.Update 每帧 ProcessModifiedCells：邻居通知延后到下一帧这里（OnBlockAdded 里读邻居是"未通知态"）SubsystemTerrain.cs:66, :493-497

深读：04页（data 位/变体表）、05页（区块状态机十态）。

链 5 · 电路一步（10ms）

#发生什么出处
1SubsystemElectricity.Update 累加器补齐 dt（单帧最多 10 步）→ while(≥0.01s)：先 UpdateElectricElements+CircuitStep++，后取本步队列（本步新建元件当步即 Simulate）SubsystemElectricity.cs:398-404（15页）
2逐元件 Simulate()：读输入电压 → 改状态/调机构子系统；返回 true = 把邻居排到下一步（信号一跳=1步=10ms）SubsystemElectricity.cs:414-423, :523-525
3机构执行：元件 Simulate → FindSubsystem&lt;SubsystemXxxBlockBehavior&gt; → 改地形/开门/发射（最终汇入链 2 的 ChangeCell）15页"机构执行类标准状态机"
4⚠ Simulate 抛异常 = catch 后 throw; 全电路死——元件内部必须兜住SubsystemElectricity.cs:415-423

链 6 · 世界加载与保存

加载（完整行号链见 11页"加载全链"）：

#发生什么出处
1选世界 PlayScreen.Play → GameManager.LoadProject：开 Project.xml、派 ProjectXmlLoad 钩子GameManager.cs:32-55
2new ProjectData：读 &lt;Subsystems&gt;/&lt;Entities&gt;（存档值 ApplyOverrides 盖在模板袋上，Type 未知静默丢）ProjectData.cs:26-54
3new Project 七步：子系统构造（只 Initialize 不 Load）→ 实体组件构造 → BeforeSubsystemsAndEntitiesLoad → 子系统按 Dependencies 递归 Load → 组件 Load（异常=Error loading component）→ OnProjectLoadedProject.cs:42-108（11页）
4GameLoadingScreen 状态机收尾进 GameScreenGameLoadingScreen.cs:21-96（17页）

保存：失焦/离屏/每 300 真实秒/手动 → Project.Save（游戏线程，Count&gt;0 才落盘）→ Task.Run 后台：.bak 轮换 → ProjectXmlSave/OnProjectXmlSaved 钩子 → UTF-8 写盘；钩子抛异常=不写文件（GameManager.cs:118-157）。

使用姿势

  • 找挂点：先在本页找到链上位置 → ⚡ 处查 Mod钩子明细 签名 → 没有现成钩子就沿"出处"列的类找 Subsystem/Component 继承点（配方页"子系统与存档"节）。
  • 查断点：现象停在哪一步，去那一步的类里打断点/日志；链 1~2 的位置类几乎都在 ComponentMiner/SubsystemTerrain 两个文件里。
  • 对应端到端示例：链 1+2 → Mod示例-代码方块；链 4 → Mod示例-自定义生物；链 6 → Mod示例-数据驱动（存档兼容）。
