内嵌浏览器（WASM/Emscripten 平台后端）

域: SC引擎 · 更新: 2026-10-31 · 状态: 全读13/13(Engine.Browser 12 + Survivalcraft.Browser 1) · 辅读: main.js 全读 / wwwroot 5 静态资产全读(A29) / Native 4 个 .c / 3 个 csproj + Browser.props

一句话定位

把整个 SC 引擎跑进浏览器的 WASM 后端：JS 采集输入与宿主服务，共享内存零拷贝喂帧，OpenAL 出声，OPFS 存档，Content.zip 由 JS 流式下载进 WASM 内存。

核心机制

1. 三层结构与程序集形态

  • 平台壳层（Survivalcraft.Browser + EntitySystem.Browser）：csproj 组合根——引用 Native C 桩、main.js、构建补丁任务；只含 1 个 .cs（ContentFileBridge）。
  • 互操作层（Engine.Browser，12 个 .cs）：BrowserInterop/Emscripten/OAL 族 + 输入共享内存协议。
  • 程序集形态：Engine.Browser.csproj 通过 Engine.props 的 &lt;Compile Include="..\Engine\**\*.cs"&gt; 把引擎核心源码与浏览器胶水编进同一个 Engine.dll（Engine.props:5 AssemblyName=Engine；Engine.Browser.csproj 另外补链 EGL.cs、剔除 Serialization 的 Archive/Serializer）——所以核心 Window.cs 能直接 #if BROWSER 调 InputBridge，main.js 也从 Engine.dll 导出表取 Engine.Browser.BrowserInterop(main.js:65-66)。EntitySystem.Browser 同构产出 EntitySystem.dll。
  • 浏览器构建移除 Jint 与 HarmonyX（Survivalcraft.Browser.csproj:13-14）：脚本引擎与运行时注入在 Web 端不存在。

2. 输入：JS→C# 共享内存双缓冲协议

  • 建链：Window.InitializeAll（BROWSER 分支）调 BrowserInterop.Initialize(InputBridge.Initialize())（E:\SurvivalcraftAPIProject\Engine\Engine\Window.cs:879）。InputBridge.Initialize（InputBridge.cs:12-18）按 16 字节对齐分配 SharedInputMemory 并把指针交给 JS。
  • JS 侧 setModuleImports("main.js").initialize（main.js:455-636）记住指针，随后每 rAF 跑 pollInputLoop（main.js:161-221）：往 ActiveIndex 指向的缓冲写状态快照（canvas 物理像素尺寸/鼠标位置/4 只手柄摇杆+扳机，main.js:164-188），手柄按键用上一帧掩码异或出边沿事件（main.js:190-218）。
  • C# 消费在每帧最前：Window.BeforeFrameAll 调 InputBridge.BeforeFrame（Window.cs:906；InputBridge.cs:20-36）——Interlocked.Exchange 原子翻转 ActiveIndex(:24-27) → 读 JS 刚写完的那块(:29) → ProcessStates(:31) → ProcessEvents(:33) → 清零该缓冲 UsedBytes 供下轮复用(:35)。
  • 状态快照不经过事件：CanvasSize 变化直接触发 Window.ResizeHandler（InputBridge.cs:41-44，Window.Size 的 BROWSER 分支返回 InputBridge.CanvasSize，Window.cs:210）；鼠标绝对位置直写 Mouse.m_currentMousePosition(:45-47)；手柄摇杆/扳机直写 GamePad.m_states(:48-57，摇杆 Y 取负)。
  • 渲染循环本体也由 JS 泵驱动：SubscribeToEvents 用函数指针把 [UnmanagedCallersOnly] 的 BrowserRenderFrameHandler 挂进 emscripten_request_animation_frame_loop（Window.cs:830；处理器 :711-715），每帧走引擎统一的 RenderFrameHandler。

3. 事件流编码（4 字节/12 字节）

  • 单事件带类型高位判长：ProcessEvents 检查 (byte)type &amp; 128（InputBridge.cs:60-81）——大事件 12 字节（SmallEvent 头+float X+float Y，LargeEvent.cs:4-9），小事件 4 字节（SmallEvent.cs:4-9：Type|Param|Payload）。
  • 小事件表（InputEventType.cs:2-16）：KeyDown(1，Payload=字符码，InputBridge.cs:85-91 转发 ProcessKeyDown+ProcessCharacterEntered)、KeyUp(2)、GamepadButtonDown/Up(3/4)、GamepadDisconnected(6)、FocusChange(64)、FullscreenChange(65)。GamepadConnected(5) 未使用——连接事件带字符串 id，走 interop（InputEventType.cs:11 注释，main.js:553-559）。
  • 大事件表（InputEventType.cs:18-27）：MouseDown/Up(128/129)、MouseMove(130，X/Y=移动距离)、MouseWheel(131，JS 除以 100，main.js:547-551；C# 侧 Y 取负累加，InputBridge.cs:124-127)、TouchDown/Up/Move(132-134，Param=pointerId%10)。
  • JS 写入端把三字段打包进一个 int32 一次 setInt32（main.js:121-139），事件总字节数超过 4096 静默丢弃（main.js:128-130、:147-149）。
  • 坐标统一物理像素：JS 用 offsetX × devicePixelRatio（main.js:499-531），canvas 实际尺寸由 ResizeObserver 上报（含 resize_canvas 消息转发给渲染 worker，main.js:458-480）。
  • 键值/按键号转换都在 JS 完成：translateKeyCode（main.js:223-402，Web code→引擎 Key 枚举序号）、鼠标中/右键互换（main.js:404-413）、手柄 standard mapping→引擎按钮号（main.js:415-448，只收 mapping==="standard"，main.js:174）。
  • 合成 Esc：指针锁定丢失（main.js:569-575）与浏览器后退键（popState，main.js:603-609）都会写一对 KeyDown(20)/KeyUp(20)——引擎把两者都当 Escape。

4. JS↔C# 互操作三通道与性能边界

  • 通道一 JSImport：BrowserInterop.cs:8-77 声明 22 个 partial 方法，运行时绑定到 runtime.setModuleImports("main.js", {...})（main.js:454-774）。窗口服务：标题(:637-638)、语言 navigator.language(:639)、关闭/刷新(:640-641)、新标签开 URL(:643，调用方 E:\SurvivalcraftAPIProject\Survivalcraft\Managers\WebBrowserManager.cs:21)、全屏(:744-754)、虚拟键盘=window.prompt(:755-757，调用方 E:\SurvivalcraftAPIProject\Engine\Engine.Input\Keyboard.cs:547)。
  • 通道二 JSExport：OnGamepadConnected(BrowserInterop.cs:79-80)与 OnDrop(:82-87，拖文件字节→Window.FileDropHandler)由 JS 回调（main.js:557、:583）。
  • 通道三 共享内存：见 §2/§5，零拷贝、无 interop 开销。
  • 性能红线（main.js:66 原注释）："调用这个特别慢，屏幕刷新率过高甚至会因此导致卡顿，能少用就少用"——高频数据一律走通道三，interop 只留给低频服务。
  • JSObject 句柄要显式 Dispose：Storage.ChooseFile 的先例（E:\SurvivalcraftAPIProject\Engine\Engine\Storage.cs:737-753：file.Dispose/bytes.Dispose）；byte[] 传回靠 returnSelf 恒等函数（main.js:717；BrowserInterop.cs:58-59）。
  • 浏览器系统字体（Local Font Access API，仅 Chromium）：IsLocalFontsSupported/QueryLocalFontsData/GetLocalFontBlob（BrowserInterop.cs:38-47；main.js:648-676）——首调 queryLocalFonts 弹权限（须用户手势），枚举结果 JS 侧缓存；ttc 各面共享同一 blob。消费方 E:\SurvivalcraftAPIProject\Survivalcraft\Managers\Fonts\FontLocator.Browser.cs:95-163（按 family/style 候选表挑面、同字节去重）。

5. Content.zip 流式下载桥

  • JS downloadContent（main.js:34-56）：fetch("./assets/Content.zip") 边下边把分块写进 WASM 线性内存 sharedContentMemoryPtr + 8（前 8 字节让给 C#），指针未就绪的块先进 pending 队列(:47-48)；下完 Atomics.store 把首字节置 1(:40-44)。
  • C# 端 ContentFileBridge.Initialize（ContentFileBridge.cs:8-14）按 ContentFileInfo.FileSize + 8 分配共享区；SetContentPtr 把指针给 JS（BrowserInterop.cs:73-74）。
  • 引擎启动时（SurvivalCraftModEntity 打开根 mod 的 BROWSER 分支，E:\SurvivalcraftAPIProject\Survivalcraft\ModsManager\SurvivalCraftModEntity.cs:42-48）：SetContentPtr → while (!GetIsDownloaded()) Thread.Sleep(100) 忙等 → GetStream()（=偏移 8 起的 UnmanagedMemoryStream，ContentFileBridge.cs:16）→ ZipArchive.Open。
  • GetIsDownloaded 是共享区首字节的 Volatile.Read（ContentFileBridge.cs:18），与 JS 的 Atomics.store 构成跨线程就绪旗标。
  • ContentFileInfo.FileSize 是编译期常量：构建前任务跑 GenerateContentInfo.csx 生成 ContentFileInfo.g.cs（csproj UpdateContentFileSize Target，BeforeBuild）。
  • 非浏览器分支对照：外置 app:/Content.zip 或内嵌程序集资源（SurvivalCraftModEntity.cs:50-64，另见 20-内容与资源管理）。

6. 文件系统：WASMFS + OPFS 挂载与软链

  • emcc 旗标含 -s WASMFS -s FORCE_FILESYSTEM -lopfs.js（Survivalcraft.Browser.csproj:5）。
  • Storage 初始化时 MountOPFS("/__root__")（Storage.cs:59）——DllImport 直达自编译的 wasmfsHelper.c:7-10（OPFS 后端建目录）。
  • 所有业务目录靠软链映射到持久层：EnsurePathLinked（Storage.cs:820-845）对任意顶级目录建 /X → /__root__/X 软链（CreateSymlink，wasmfsHelper.c:15-16；errno 17 EEXIST 视为成功），__root__/dev/tmp 三个名字跳过(:816)——即引擎看到的文件树根其实都落在浏览器 OPFS 里。
  • 用户磁盘交互走 File System Access API：ShareFile=showSaveFilePicker+写句柄（Storage.cs:691-695），ChooseFile=showOpenFilePicker+字节拷回（Storage.cs:737-753）。

7. 音频：OpenAL 直连

  • Mixer.Initialize BROWSER 分支 new ALContext() + new AL()（E:\SurvivalcraftAPIProject\Engine\Engine.Audio\Mixer.cs:34-35），用 using 别名把 Engine.Browser 的 AL 族顶替 Silk.NET.OpenAL（Mixer.cs:3-7）——上层音频代码零改动（另见 08-音频系统）。
  • ALContext 构造链：alcOpenDevice(null)→失败仅 Log.Error→alcCreateContext→alcMakeContextCurrent（ALContext.cs:6-14）；Dispose 反向销毁(:16-26)。
  • OAL 库名常量 "openal32"（OAL.cs:7）由 emscripten 解析到 -lopenal；openal32.c 只 include AL 头(:1-2)，真实现来自 emscripten 移植层。AL.cs 提供类型化枚举+流式 Queue/Unqueue 封装(:84-126)。

8. GL 蹦床与 native 桩

  • GL 上下文建立后、GL.GetApi(Egl.GetProcAddress) 前调 TrampolineFuncs.ApplyWorkaroundFixingInvocations()（E:\SurvivalcraftAPIProject\Engine\Engine.Graphics\GLWrapper.cs:204-205）。
  • TrampolineFuncs.cs 本体只有两样东西：[DynamicDependency] 锚方法(:8-11)防裁剪器把这 280 个 [UnmanagedFunctionPointer] GL 委托类型剪掉(:14-2574)——委托签名存续是 WASM AOT 生成原生调用蹦床的前提，全文无逻辑。
  • libEGL.c 给 emscripten 缺失的 eglCreatePbufferSurface 补桩返回 EGL_NO_SURFACE（libEGL.c:5-9，注释言明仅 WINDOWS 无头渲染路径会调到）。
  • 渲染跑在 worker+OffscreenCanvas：emcc -s OFFSCREENCANVASES_TO_PTHREAD=#canvas -s OFFSCREEN_FRAMEBUFFER=1（csproj:5），主线程 ResizeObserver 把新尺寸 postMessage 给 worker 的 resize_canvas 命令（main.js:472-479）。

9. 浏览器构建壳（AOT/补丁/裁剪）

  • Browser.props：net10.0 + browser-wasm + BROWSER 宏、PublishTrimmed=full、RunAOTCompilation、WasmEnableThreads/SIMD、WasmEnableExceptionHandling=false、WasmStripILAfterAOT。
  • EmccInitialHeapSize 386662400 与 main.js INITIAL_MEMORY 一致（csproj:6；main.js:62）。
  • PatchJs.csx 构建后给 dotnet.native.js/worker.mjs 打 4 处补丁：注释掉 emscripten 自带 _egl* JS 实现（让位给 libEGL.c 原生版）、注入 canvas 未转移时的 #canvas 兜底转移、WASMFS createPath 改为直接拼接、worker 增加 resize_canvas 命令处理（PatchJs.csx 全文）。
  • main.js 启动硬性要求 SharedArrayBuffer（main.js:2-6），缺了直接在页面上报错；PWA 由 service-worker.js+manifest.json 支撑。
  • 首帧就绪回调：ContentLoaded 后 BrowserInterop.FirstFramePrepared()（E:\SurvivalcraftAPIProject\Survivalcraft\Game\Program.cs:356）→ JS 摘掉 splash（main.js:770-773）；语言来源 BrowserInterop.GetLanguage()（Program.cs:198）。
  • 另有最小渲染测试入口 Main2/Frame（Program.cs:50-74，画一条对角线自检）。

坑与对策

  • interop 高频调用卡帧：JSImport/JSExport 每次跨界开销大（main.js:66 注释明言高刷屏会卡）→ 高频数据抄 InputBridge 共享内存模式，interop 只做低频服务。
  • 事件缓冲 4096 字节溢出静默丢：JS 写入端超限直接 return，无任何上报（main.js:128-130）→ 别在单帧塞大量事件；新事件类型先算字节数预算。
  • 手柄非 standard mapping 全盲：mapping!=="standard" 直接 continue（main.js:174）→ 自定义手柄在浏览器端不出输入是正常现象，不是引擎 bug。
  • 指针锁定丢失=合成 Esc：锁定被浏览器打断会注入一对 Esc 按键（main.js:569-575）→ 依赖 Esc 打开菜单的逻辑在浏览器会"意外"收到 Esc，属设计行为。
  • Content.zip 尺寸是编译期常量：只换 zip 不重编浏览器壳 → FileSize 失配，ZipArchive 读到截断/多余流 → 改 Content.zip 必须重跑 UpdateContentFileSize（csproj BeforeBuild 自动，手动拷贝发布才会踩）。
  • 启动忙等下载：SurvivalCraftModEntity 阻塞等 Content.zip 下完（SurvivalCraftModEntity.cs:43-45），慢网=长黑屏，进度条只有 JS splash 动画（main.js:17-23）。
  • 浏览器构建没有 Jint/HarmonyX（csproj:13-14）→ 依赖运行时注入/脚本求值的特性在 BROWSER 下必须不可达，否则运行期崩。
  • JSObject 句柄泄漏：跨界的 file/bytes 对象不 Dispose 会钉住 JS 堆 → 照抄 Storage.ChooseFile 的 using/Dispose 序（Storage.cs:749-753）。
  • 鼠标按键号互换：JS 端中/右键映射互换（main.js:404-413）→ 在 JS/C# 两侧对按钮号做判断时以引擎 MouseButton 为准，别拿浏览器 event.button 直接比。
  • 滚轮符号与单位：JS 除以 100（main.js:550），C# 再对 Y 取负（InputBridge.cs:125）→ 自己扩展滚轮逻辑时先在两端各打一份数值对照。
