实体与组件体系

域: SC引擎 · 更新: 2026-11-01 · 状态: 全读(组件 91/91 + EntitySystem 20/20；91 个组件文件全部逐文件全文实读，逐文件行号明细见 03a-组件明细)

一句话定位

Entity 是组件容器，Component 的行为靠 8 个虚方法 + IUpdateable 接口驱动，模板是 DatabaseObject 树上的数据节点而不是类。

核心机制

Component 虚方法表与调用时机

调用链统一是 new Entity(project, valuesDictionary, id) → 遍历模板袋 → component.Initialize → …。Entity 构造在 Entity.cs:87-132，只接受 EntityTemplate 类型的袋子(:88-90)。

虚方法声明处调用时机与调用点
Initialize(entity, vd)Component.cs:41-47构造期间，每个组件建好后立即调(Entity.cs:121)。override 必须调 base，否则 ValuesDictionary 全 null
OnEntityAdded()Component.cs:24进世界加载时：所有组件 Load 完才统一派发(Project.cs:256-261 → :316-325)；运行时 AddEntity 即派发(Project.cs:192-194)
Load(vd, idToEntityMap)Component.cs:28Project ctor 第 7 步，全体子系统 Load 之后(Entity.cs:206-215)；实参就是组件自己的 ValuesDictionary(Entity.cs:209)
Save(vd, entityToIdMap)Component.cs:30每次 Project.Save() 写进新建的空袋(Entity.cs:219)，Count>0 才以组件名为键落盘(Entity.cs:221-223)
OnEntityRemoved()Component.cs:26RemoveEntity 时，组件先于子系统(Project.cs:327-336)
Dispose()Component.cs:32RemoveEntity(entity, disposeEntity:true) 或 Project.Dispose 逐实体调(Entity.cs:185-189)
InheritFromComponent(base)Component.cs:34仅 Entity.ReplaceComponent 调；全仓无实现无调用，死代码
GetOwnedEntities()Component.cs:20SaveEntities 时排除被拥有的实体(Project.cs:338-356)

没有 Simulate、没有 Init、没有 Update——组件每帧逻辑必须实现 IUpdateable(见下)。

每帧更新：IUpdateable + UpdateOrder

  • 组件声明 class X : Component, IUpdateable(IUpdateable.cs:2，Update(float dt) :6)。注册/摘除：SubsystemUpdate.OnEntityAdded/Removed 扫 FindComponents<IUpdateable>(SubsystemUpdate.cs:179-189)。
  • 派发：每 tick 按 FloatUpdateOrder 升序逐个 Update(dt)(SubsystemUpdate.cs:90-95)；Update 抛的异常被 catch (Exception) {} 彻底静默(:97-99)。
  • UpdateOrder 枚举实为 12 值(UpdateOrder.cs:2-16)：Reset=-100(ScreenOverlays/AimingSights，先清叠层)、SubsystemPlayers=-20、Input=-10、Default=0、Locomotion=1、Body=2、CreatureModels=10、FirstPersonModels=20、BlocksScanner=99、Terrain=100、Views=200、BlockHighlight=201。可重写 FloatUpdateOrder 插小数——骑乘时 ComponentBody 返回 父body.FloatUpdateOrder+0.01f(ComponentBody.cs:256-261)；CreatureModel 骑乘时返回骑坐骑模型 UpdateOrder+1(ComponentCreatureModel.cs:85-96)。

组件互查：FindComponent 家族(Entity.cs:134-183)

调用语义
entity.FindComponent<T>() (:167)按类型找第一个，找不到返回 null
entity.FindComponent<T>(throwOnError:true) (:169)找不到抛 Required component {类型全名} does not exist in entity.(:143)
entity.FindComponent<T>(name, throwOnError) (:171)name 比的是组件袋子名(DatabaseObject.Name)；同名组件多个时用这个区分
entity.FindComponents<T>() (:183)迭代器遍历全部，is T 过滤，同一类型多实例用它

原版互查范式：ComponentCreature.Load 硬抓 6 个兄弟组件(ComponentCreature.cs:42-47)；ComponentPlayer.Load 抓 14 个(ComponentPlayer.cs:590-603)。反向：Entity.RemoveComponent(:173-175) 仅移除不 Dispose。

实体的两条创建路 + 销毁

  1. 进世界：Project ctor → InitializeEntities(Project.cs:224-246) → AddEntities(:84)。
  2. 运行时生成：DatabaseManager.CreateEntity(project, templateName,…)(Survivalcraft\Managers\DatabaseManager.cs:77-92) → Project.CreateEntity(Project.cs:169-179) → Project.AddEntity。
  3. 第三条路（少数）：Project.CreateEntity(new ValuesDictionary().PopulateFromDatabaseObject(模板))——开场 IntroShip 就这么建(ComponentIntro.cs:75-86)。
  4. 销毁：RemoveEntity(entity, disposeEntity)(Project.cs:198-210)；生物消散走 ComponentSpawn.Despawn→Update 到点 Project.RemoveEntity(Entity,true)(ComponentSpawn.cs:54-60)。

生命/伤害结算链

  • 入口：ComponentHealth.Injure(amount, attacker, ignoreInvuln, cause)(ComponentHealth.cs:149) → Injure(Injury)(:154)：Health>0 才受理 → injury.Process()(:161) → ≤0 过 OnCreatureDying hook(:163) → Die(injury)(:172)。
  • Die(:178-248)：经验球数 ceil(AttackResilience/12)；OnCreatureDied hook 改数量；击杀统计按 CreatureCategory 分桶；>100 球成组掉落防卡顿(:216-246)。
  • Update(:250-435) 单帧顺序：再生(玩家睡觉 0.00167/s、Harmless 0.0167/s :253-272) → 溺水空气(Air 模式按眼部所在格判水 :276-281) → 岩浆(:289) → 跌落(:304) → 虚空(y<0‖y>296 :318) → 溺水(:325) → 火(:332) → 挤压(:338) → 鱼搁浅(:348) → 表现结算(血条闪烁 clamp(-HealthChange*30,0,10) :361，红屏过 ChangeVisualEffectOnInjury hook :372) → 死亡掉落(遍历 FindComponents<IInventory>() DropAllItems，Clothing 也是 IInventory 所以衣服会掉 :421-427) → 尸体超 CorpseDuration → Spawn.Despawn(:429)。
  • 抗性双轨：m_xxxResilience * XxxFactor getter(:88-107)；环境抗性是独立属性 VoidDamageFactor/AirLackResilience/Magma/Crush/Spike/Explosion(:28-33)；多数伤害再 /Factors.ResilienceFactor。
  • 近战伤害生成端：ComponentMiner.DoMeleeHit(ComponentMiner.cs:636-715)——伤害 GetMeleePower(手持)*AttackPower*rand(0.8,1.2)、命中率空手 0.66/静止目标×2(:649)、×StrengthFactor(:676) → MeleeAttackment.ProcessAttackment(:1107-1114) → 耐久 DamageActiveTool(:1089)。AI 打人也走这条：ChaseBehavior 只置 AttackOrder，命中帧调 m_componentMiner.Hit(Behavior\ComponentChaseBehavior.cs:180)。
  • 非生物（船/载具）用平行的 ComponentDamage(ComponentDamage.cs:39-80)：Hitpoints≤0 直接 RemoveEntity，与 Health 互不相通。

属性因子系统（ComponentFactors → ComponentLevel）

  • ComponentFactors(ComponentFactors.cs)：四基础因子列表(强度/速度/饥饿/抗性) + OtherFactors 字典(预置 AttackSpeed/DigSpeed/ChaseRange :99-101) + 结果缓存。CalculateFactorsResult(:105-126) 逐项 Multiply/Add，NaN/Inf 回退 1。Update 时序(:199-214)：先结算上一帧结果 → 再 Generate 清空重建 → 末尾 OnFactorsUpdate hook。GetOtherFactorResult 缺键默认返回 1(:59)。
  • 生效点：AttackSpeed 除进 Miner.HitInterval(ComponentMiner.cs:62-66)；DigSpeed 乘进 DigSpeedFactor(:98-109)；ChaseRange 乘昼/夜仇恨距离(Behavior\ComponentChaseBehavior.cs:284)；SpeedFactor 乘移速/跳速(ComponentLocomotion.cs:413,507)；ResilienceFactor 除进溺水/火/摔落伤(ComponentHealth.cs:328,334,58)。
  • ComponentLevel : ComponentFactors(ComponentLevel.cs:12)：每帧覆写引擎槽位——强度 8 槽(女 0.8/等级 +5%/体力/病/流感/模式 :141-163)、抗性 5 槽(创造=+∞，即创造免伤的实现点 :187-189)、速度 7+ 衣物槽(:197-224)、饥饿 3 槽(:229-249)、Wetness OtherFactor(:254-288)。槽位对象跨帧复用(:52-61)——模组持有引用读到最新值，自 Add 的 Factor 每帧被清。经验：每球 0.012/1.08^(lvl-1)(:83)。

库存模型（IInventory 六实现）

  • 接口契约由 ComponentInventoryBase(ComponentInventoryBase.cs:7) 实现：List<Slot{Value,Count}>(:14)，容量=BlocksManager.GetMaxStacking(:137-143)。AddSlotItems 在 value 不符/超容时抛 InvalidOperationException(:170-180)。
  • 静态工具：FindAcquireSlotForItem(先同值未满栈后空格 :32-47)、AcquireItems(返回塞不下的余数 :49-59)、DropSlotItems→SubsystemPickables(:73-86)。ProcessSlotItems 委托给 SubsystemBlockBehavior(:186-211)。
  • 派生格数约定：熔炉 Fuel=SlotsCount-3/Result=-2/Remains=-1(ComponentFurnace.cs:62-66)；合成台产物格=SlotsCount-2、grid=sqrt(SlotsCount-2)(ComponentCraftingTable.cs:20,124)。
  • 五种 IInventory：Inventory(生存 10 格)、Chest/Dispenser/Furnace/CraftingTable(继承 Base + 挂 BlockEntity.m_inventoryToGatherPickable 自动吸物)、CreativeInventory(OpenSlots+全部 CreativeValues)、Clothing(槽= ClothingSlot，GetSlotValue 取最后一件，Layer 递增才可叠穿 ComponentClothing.cs:415,567-584)、FurnitureInventory(虚拟)。存档：Slots 子袋只存 Count>0(ComponentInventoryBase.cs:104-116)。
  • 护甲：ComponentClothing.ApplyArmorProtection(Attackment)(ComponentClothing.cs:165-257)——随机选槽(脚 10%/腿 20%/躯干 60%/头 10% :185-188)→ 逐件 ClothingData.ApplyArmorProtection → 移除已毁 → 按 Layer 排序回写。服装贴图合成为 RenderTarget(:586-709)，ShowClothedTexture/DrawClothedTexture 是 static 开关(:76-83)。

生物 AI 调度链

调度链：ComponentBehaviorSelector.Update(ComponentBehaviorSelector.cs:14-37，每帧选 ImportanceLevel 最大者置 IsActive，Health>0 且未嵌冰才选) → ComponentBehavior 子类状态机抬/压自己的 importance(Behavior\ComponentBehavior.cs:4-10) → 选中行为写 ComponentPathfinding.SetDestination(ComponentPathfinding.cs:63，状态机 Stopped→MovingDirect→SearchingForPath→MovingWithPath→Stuck，拥塞预算 500/上限 1000/衰减 20/s :33-39) → ComponentPilot(ComponentPilot.cs:106，避障 AvoidNearestBody:341 + 地形安全 IsTerrainSafeToGo:249 + 卡住检测 4 次:127-140) → order 合并进 Locomotion(CombineNullables 相加，ComponentPilot.cs:229-234) → ComponentLocomotion.Update 消费并清空一帧指令(:301-313)。

  • importance 梯度：FishOutOfWater 1000 > CetaceanBreathe 400 > 逃跑族 300(低血)/100 > Steed 275 > Summon 270 > AvoidFire/Herd 250 > DumpRider 220 > StubbornSteed 210 > Chase 200 > 其余 0-10。逐行为见 03a。
  • ChaseBehavior(Behavior\ComponentChaseBehavior.cs)：三入口自动开战——碰撞(:225-245，ChaseOnTouchProbability+AutoChaseMask)、被击(:246-267，概率≥1 时持久追 30/60s)、主动索敌(需连续 TargetInRangeTimeToChase=3s 可见 :287-297)；攻击执行=置 Model.AttackOrder → 模型 IsAttackHitMoment 帧 → GetHitBody 射线校验(:552-568) → Miner.Hit(:180)；目标死亡→延迟调 RandomFeedBehavior.Feed(:355-366)。
  • 群体：HerdBehavior.CallNearbyCreaturesHelp(Behavior\ComponentHerdBehavior.cs:35-63) 16² 内同名 HerdName 且 Chase 空闲者集体 Attack（挤奶 ComponentUdder.cs:25 与受击 :120-123 都会触发）。

模板(Template)机制速览

  • "模板"= Database.xml 里的 DatabaseObject 节点，九种类型由 GameDatabase 抓成属性(GameDatabase.cs:25-36)。
  • EntityTemplate 的有效嵌套孩子里，Parameter 变键、容器节点递归成子袋(ValuesDictionary.PopulateFromDatabaseObject :107-125)；%…% 引用就地求值(ProceduralValue.cs:11-101)。
  • 组件挂接：Entity ctor 遍历袋里 MemberComponentTemplate 子袋(Entity.cs:94-98)，读 Class 字符串 → TypeCache.FindType → Activator.CreateInstance(必须 public 无参构造 :107)。Class 与组件类之间零编译期检查。
  • 继承两条链(DatabaseObject.cs)：显式 InheritanceParent + 隐式"嵌套父的继承父里同名孩子"(:212-219)；同名遮蔽=显式孩子占名(:424-439)。
  • 模板细节与 .xdb 合并语义另见百科 07-entity/01-ecs-concepts、07-entity/03-xdb-registration、04-data/xdb-format，本页不复制。

加载失败的表现链

  1. 组件实例化抛 → Error creating entity from template "X".(Project.cs:238-243)。
  2. 组件 Load 抛 → Error loading component {类全名}.(Entity.cs:211-213)，inner 是真实异常。查日志先搜这句。
  3. Class 解析不到：IsOptional=false 抛 Type "X" not found in any loaded assembly.(TypeCache.cs:102-105)；IsOptional=true 静默跳过(Entity.cs:103)——排错先去掉 IsOptional。
  4. 漏到 Project ctor 外 → Loading World Failed!(Project.cs:93-107)；存档级模板失效降级 Ignoring invalid entity(EntityDataList.cs:20-25)。

坑与对策

  • LoadOrder +10000：type.Namespace != "Game" 的组件 LoadOrder 被加 10000 排到全部原版组件后(Entity.cs:122-125)；想保持原序就写进 namespace Game，想插队用 Entity.EntityComponentsInitialized 静态事件(Entity.cs:85)。
  • ReplaceComponent 是空操作：不碰 m_components(Entity.cs:177-181)。换实现用 NoEffect/同名遮蔽/EntityComponentsInitialized。
  • GetValue<T> 硬拆箱：int 写 float 读即 InvalidCastException；TryGetValue 类型不符也抛(ValuesDictionary.cs:82-89)。详见 11-存档持久化。
  • Update 异常静默：IUpdateable.Update 抛错被吞(SubsystemUpdate.cs:97-99)，"逻辑没跑"先包 try/catch 自证。
  • 同名组件顶键：存档按组件名写键(Entity.cs:222)，同实体两个同名组件 Save 互相覆盖；同类型多实例必须带名查(Entity.cs:171)。
  • ComponentCreature 六件套硬依赖：少挂 Body/Health/Spawn/CreatureSounds/CreatureModel/Locomotion 之一直接抛(ComponentCreature.cs:42-47)；CreatureModel 是抽象类，必须给具体模型。
  • RemoveComponent 不 Dispose：仅摘列表(Entity.cs:173-175)。
  • 别在 Initialize 里做业务初始化：其余组件未实例化(Entity.cs:121 逐个调)，互查放 Load；Load 早于子系统 Load。
  • 四足/鸟/鱼模型无控制器=完全静止：AnimateCreature 空实现(ComponentFourLeggedModel.cs:188 等)，仅 HumanModel 有后备动画。
  • InventoryBase.AddSlotItems 抛异常：value 不符/超容都 throw(ComponentInventoryBase.cs:170-180)，批量塞格先查 GetSlotCapacity。
  • Clothing 贴图开关是 static：ShowClothedTexture/DrawClothedTexture(ComponentClothing.cs:76-83)，一个玩家的 glTF 参数会改全局。
