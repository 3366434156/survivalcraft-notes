数据格式参考 2 · 配方/衣物/实体参数

域: SC引擎 · 更新: 2026-11-01 · 状态: 全读（三个解析器+原版 XML/XSD 实读）

一句话定位

CraftingRecipes.xml、Clothes.xml、Database.xml 参数键的 schema 与值语法，AI 写这三类数据文件按属性名直接落笔。

怎么用（AI 视角）

  1. 写 .cr/.clo/.xdb 前：查本页对应属性表 → 抄"最小可用示例"；属性名一字不差，大小写敏感。
  2. 方块数据表（.csv 78 列）见 数据格式参考；装载链与合并协议另见 01-引擎/12-ModAPI与加载链.md。

一 · CraftingRecipes.xml（配方）

解析器：E:\SurvivalcraftAPIProject\Survivalcraft\Managers\CraftingRecipesManager.cs（DecodeElementToCraftingRecipe :85-138）。原版样例：E:\SurvivalcraftAPIProject\Survivalcraft\Content\Assets\CraftingRecipes.xml（1098 行）。结构：根 &lt;Recipes&gt; → 分类文件夹（&lt;Smelting&gt;/&lt;Materials&gt; 等，仅归档不参与匹配，XSD CraftingRecipes.xsd:10-26 枚举 17 类）→ &lt;Recipe&gt;。无 Result 属性的元素一律递归下钻（CraftingRecipesManager.cs:59-66）；单条解析失败仅 Log.Error 不崩、不中断兄弟条目（:80-82）。

机制要点（实读）

  • :N 是 data 不是数量：成分值 seeds:5 = 种子方块 data=5（Rye 种子），数量由网格字符个数决定（CraftingRecipesManager.cs:215-217）。
  • 匹配允许平移+镜像：9 格内任意平移、左右翻转都匹配（MatchRecipe :220-259；TransformRecipe :261-282）；成分带 data 时实际 data 必须相等，不带 data 时任意 data 均可（CompareIngredients :284-304）。
  • 程序化配方：Block 子类可代码产出（GetProceduralCraftingRecipes，:27），与 XML 配方同列表排序。
  • mod 合并（.cr 文件，ModEntity.cs:365-378 装载）：New-属性 改同款配方（同款=除该属性外其余属性全等+网格文本逐行相等，ModsManager.cs:898-935）；r- 或 Remove 属性删同款（:983-987）；无前缀=追加新配方（:989）。

坑与对策

  • 成分 :N 误当数量：a="seeds:5" 是 data=5 不是 5 个；要数量就在网格里多写几个字符（CraftingRecipesManager.cs:215-217）。
  • Description/ResultCount 等标"必填"的属性缺失=该条配方抛异常被吞：整条消失只剩 Log.Error，注意比对原版条目数（XmlUtils.cs:11-17 无默认重载缺属性即抛）。
  • 新组件模板漏键=实体加载崩：GetValue 缺键抛异常（ValuesDictionary.cs:38-42）；要么 InheritanceParent 继承基模板 GUID，要么把该组件 Load 读的键补全（基模板默认值抄 Database.xml:4170-4190 一类）。
  • KillVerbs 忘写：ComponentCreature.Load 直接抛"Must have at least one KillVerb"（ComponentCreature.cs:59-61），新生物模板必带。
  • .cr 改同款配方网格也变了：New- 覆写会把目标配方的网格文本一并替换成你的（element1.SetValue，ModsManager.cs:980）——只想改产物也要把原网格原样抄进自己的 .cr。
  • 枚举大小写敏感：Air/Water/Meat/LandOther 首字母大写，错值解析失败。
